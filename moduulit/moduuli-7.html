Konteksti, /compact ja /clear

Claude muistaa vain sen, mikä on keskustelun kontekstissa: viestit, lukemasi tiedostot ja komentojen tulosteet. Konteksti on rajallinen, ja pitkässä keskustelussa se täyttyy, jolloin vastaukset huononevat ja kulutus kasvaa.

  • /context näyttää, mitä konteksti sisältää.
  • /compact tiivistää keskustelun ja jatkaa samaa työtä. Voit ohjata tiivistystä: /compact keskity skriptin virheisiin.
  • /clear aloittaa tyhjästä. Käytä sitä, kun siirryt aivan toiseen tehtävään. Edellisen keskustelun löytää komennolla /resume.
Nyrkkisääntö: yksi tehtävä, yksi keskustelu. Kun tehtävä vaihtuu, käytä /clear. Kun sama tehtävä jatkuu mutta keskustelu on pitkä, käytä /compact.

Käyttö ja rajat: /usage

Komento /usage näyttää istunnon kustannuksen ja sen, kuinka paljon tilauksesi käyttörajasta on kulunut. Raja on sama kuin claude.ai:ssa: lue periaate moduulin 0 käyttörajat-osiosta.

  • Pitkä konteksti, monta tiedostoa ja raskas malli kuluttavat enemmän.
  • Tarkista /usage ennen suurta työtä ja kun raja alkaa lähestyä.
  • Pienemmän mallin vaihto (/model) kevyisiin tehtäviin säästää rajaa.

Suunnittelutila ja /rewind

Suunnittelutila (plan mode)

Suunnittelutilassa Claude lukee ja ehdottaa suunnitelman, mutta ei muuta mitään. Vaihda tilaa näppäimellä Shift+Tab (kierto: Manual, Accept edits, Plan) tai käynnistä claude --permission-mode plan. Joillakin Windows-asetuksilla vaihtonäppäin on Alt+M.

Käytä suunnittelutilaa, kun muutos on laaja tai riskialtis: katso ensin suunnitelma, korjaa sitä ja salli toteutus vasta sitten.

/rewind

Claude Code tallentaa tilanteen ennen jokaista lähettämääsi viestiä. Komento /rewind (tai Esc kahdesti tyhjässä kehotekentässä) avaa listan, josta voit palauttaa koodin, keskustelun tai molemmat valittuun kohtaan.

Tärkeä rajoitus: palautus seuraa vain Clauden omien tiedostotyökalujen tekemiä muutoksia. Jos tiedostoa on muutettu vain shell-komennolla (Bash tai PowerShell, esimerkiksi Remove-Item tai Move-Item), muutosta ei seurata eikä /rewind kumoa sitä. Tallenna työ gitiin (moduuli 8): /rewind ei korvaa versionhallintaa.
[KUVA: m7-rewind - rewind-valikko ja palautusvaihtoehdot]

CLAUDE.md ja muisti

Jokainen istunto alkaa tyhjällä kontekstilla. Kaksi tapaa antaa Claudelle pysyvää tietoa:

  • CLAUDE.md on sinun kirjoittamasi ohjetiedosto projektin kansiossa. Se ladataan joka istunnossa. Komento /init luo siitä ensimmäisen version analysoimalla kansion.
  • Automaattinen muisti (auto memory) on muistiinpanoja, joita Claude kirjoittaa itse korjauksistasi ja mieltymyksistäsi. Ne tallentuvat käyttäjäkansion %USERPROFILE%\.claude\projects\ alle.

Hyvä CLAUDE.md on lyhyt ja täsmällinen: kerro asiat, joita Claude ei voi päätellä koodista.

# Ohjeet

- Skriptit ovat PowerShell 7 -skriptejä. Käytä Verb-Noun-nimiä.
- Älä koskaan aja skriptejä tuotantopalvelimia vastaan; kaikki testit tehdään testiympäristössä.
- Kirjoita ohjeet ja kommentit suomeksi.
- Testit: Invoke-Pester .\tests

Muistin kytkeminen pois

  • Komento /memory avaa listan ja kytkimen automaattiselle muistille.
  • Asetus "autoMemoryEnabled": false tiedostossa %USERPROFILE%\.claude\settings.json kytkee sen pois kaikista projekteista, ja projektin omassa asetustiedostossa vain siltä projektilta.
  • Ympäristömuuttuja CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 kytkee sen pois myös.

Älä kirjoita CLAUDE.md-tiedostoon salasanoja tai muita salaisuuksia: tiedosto kulkee usein repon mukana.

Luvat käytännössä

Claude Code kysyy luvan, ennen kuin se muokkaa tiedostoa tai ajaa komennon. Lukeminen työkansiossa ja tunnetut vain lukevat komennot eivät kysy.

Mitä "allow always" kirjoittaa

Kun valitset Yes, and don't ask again, Claude Code tallentaa komennolle allow-säännön projektin .claude\settings.local.json-tiedostoon (git-repossa repon juureen, Windowsissa työkansion .claude-kansioon). Sääntö on voimassa myöhemmissä istunnoissa. Tiedostokirjoitusten hyväksyntä ei tallennu: se on voimassa vain istunnon loppuun.

{
  "permissions": {
    "allow": [
      "Bash(npm test *)"
    ]
  }
}

Tarkista ja poista säännöt komennolla /permissions. Älä hyväksy pysyvästi leveää sääntöä, jota et ymmärrä.

Deny-sääntö suojaa salaisuuksia

Deny-sääntö estää Claudea lukemasta tiedostoa. Lisää se esimerkiksi käyttäjän asetuksiin %USERPROFILE%\.claude\settings.json:

{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)"
    ]
  }
}

Deny voittaa aina allow-säännön. Se koskee Clauden tiedostotyökaluja ja tunnistettuja tiedostokomentoja (esimerkiksi cat), mutta ei jokaista tapaa lukea tiedosto, esimerkiksi skriptiä, joka avaa tiedoston itse. Tiukkaan eristykseen tarvitaan hiekkalaatikko (sandbox) ja pidä salaisuudet repon ulkopuolella.

Älä ohita lupia. Lippu --dangerously-skip-permissions poistaa lupakysymykset: Claude voi silloin ajaa komentoja ja muuttaa tai poistaa tiedostoja kysymättä. Käytä sitä korkeintaan kertakäyttöisessä, eristetyssä ympäristössä (esimerkiksi virtuaalikoneessa), jossa ei ole salaisuuksia eikä tuotantoyhteyksiä. Älä koskaan käytä sitä työasemalla tai palvelimella, jolla on oikeaa dataa. Ylläpito voi kieltää tilan asetuksella permissions.disableBypassPermissionsMode.

Harjoitukset

1. Lokin tulkinta ja /compact

Edellyttää: Pro-tilaus. Ei Prota? Seuraa kouluttajan demoa (Max) tai tee parin kanssa.

Tee tiedosto loki.txt, jossa on noin 30 riviä palvelun lokia: pääosin INFO-rivejä, mutta mukana muutama ERROR, kuten "Timeout connecting to 203.0.113.15:1433" ja "Login failed for user svc-backup". Pyydä: "Lue loki.txt, ryhmittele virheet syyn mukaan ja ehdota tarkistuskohdat." Aja sen jälkeen /context ja /compact keskity virheisiin.

Näytä esimerkkivastaus

Claude ryhmittelee virheet (esimerkiksi verkkoyhteys SQL-palvelimeen ja tunnistautuminen) ja ehdottaa tarkistuskohdiksi palvelun tilan, palomuurisäännön ja tunnuksen salasanan voimassaolon. Komento /context näyttää tiedoston lisänneen kontekstia, ja /compact tiivistää keskustelun niin, että virheet säilyvät. Varmista, että tiivistyksen jälkeen Claude muistaa edelleen molemmat virheet: kysy "Mitkä virheet löytyivät?"

2. Suunnittelutila ja /rewind

Edellyttää: Pro-tilaus. Ei Prota? Seuraa kouluttajan demoa (Max) tai tee parin kanssa.

Tee kansio, jossa on PowerShell-skripti, joka poistaa yli 30 päivää vanhat tiedostot kansiosta. Vaihda Shift+Tab-näppäimellä suunnittelutilaan ja pyydä: "Lisää skriptiin -WhatIf-tuki ja loki poistetuista tiedostoista. Näytä ensin suunnitelma." Hyväksy suunnitelma, anna Clauden muokata skripti ja kokeile sitten /rewind palauttaaksesi alkuperäisen skriptin.

Näytä esimerkkivastaus

Suunnitelmassa on tavallisesti: lisätään [CmdletBinding(SupportsShouldProcess)], kutsutaan poistoa Remove-Item -WhatIf:$WhatIfPreference ja kirjataan poistetut polut lokiin. Muokkauksen jälkeen /rewind > Restore code palauttaa skriptin alkuperäiseksi, koska Clauden tiedostotyökalu teki muutoksen. Jos pyydät Claudea poistamaan testitiedostoja PowerShell-komennolla, /rewind ei palauta niitä: shell-komennon muutoksia ei seurata.

3. Suojaa salaisuudet

Edellyttää: Pro-tilaus. Ei Prota? Seuraa kouluttajan demoa (Max) tai tee parin kanssa.

Tee testikansioon tiedosto .env, jossa on keksitty rivi API_KEY=esimerkki-ei-oikea. Pyydä Claudea lisäämään sääntö, joka estää .env-tiedoston lukemisen, ja kokeile sitten pyytää sitä lukemaan tiedosto. Tarkista sääntö komennolla /permissions.

Näytä esimerkkivastaus

Claude lisää asetustiedostoon "deny": ["Read(./.env)"] (ja mahdollisesti Read(./.env.*)). Kun pyydät lukemaan tiedoston, Claude Code estää luvun ja Claude kertoo, ettei pääse tiedostoon. Sääntö näkyy /permissions-listassa. Muista rajaus: sääntö ei estä kaikkia epäsuoria tapoja lukea tiedosto, joten oikeita salaisuuksia ei silti pidä säilyttää projektikansiossa.

Lisä: istunnot ja työtavat

  • Nimeä keskustelu komennolla /clear nimi tai ota se myöhemmin esiin komennolla claude --resume "nimi".
  • Oma CLAUDE.md kotikansioon (%USERPROFILE%\.claude\CLAUDE.md) sisältää ohjeet, jotka koskevat kaikkia projekteja. Henkilökohtaiset projektikohtaiset asiat voi laittaa tiedostoon CLAUDE.local.md, jota ei viedä gitiin.
  • Esc keskeyttää Clauden kesken vastauksen; työ säilyy. Näin voit ohjata, kun Claude menee väärään suuntaan.
  • Lue lisää: muisti, luvat ja checkpointit.
