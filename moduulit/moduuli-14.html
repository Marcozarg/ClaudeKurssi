Automaatio: headless ja CI

Ydin ~30 minLisä ~15 minPro / Max

Claude ilman käyttäjää: claude -p

Tähän asti olet keskustellut Clauden kanssa. Automaatiossa ei ole ketään vastaamassa kysymyksiin: skripti, ajastus tai CI-työ antaa Claudelle tehtävän ja lukee tuloksen. Tämä on headless-ajo, ja se tehdään lisäämällä claude-komentoon valitsin -p (print):

claude -p "Mitä auth-moduuli tekee?"
cat build-error.txt | claude -p "Selitä tiiviisti, mikä tätä virhettä aiheuttaa"
  • Claude tekee tehtävän, tulostaa vastauksen ja päättyy. Onnistuessa poistumiskoodi on 0, virheessä muu kuin 0, joten skripti voi haarautua sen mukaan.
  • Putkitettu syöte (stdin) luetaan mukaan. Raja on 10 Mt.
  • Kun lupakysymys tulisi, ketään ei ole vastaamassa. Ilman erillistä lupaa kutsu, joka vaatisi hyväksynnän, evätään. Siksi luvat ja työkalut päätetään etukäteen (osio "Turvallinen ajo").
  • --output-format json antaa vastauksen JSON-muodossa: teksti on kentässä result ja arvioitu kustannus kentässä total_cost_usd. Muut muodot ovat text (oletus) ja stream-json.
Headless-ajo on sama Claude Code kuin muualla, ei kevyempi versio. Se voi lukea, muokata ja ajaa komentoja täsmälleen niillä oikeuksilla, jotka sille annat.

Ohjeet: Run Claude Code programmatically.

Skripti, joka kutsuu Claudea

Tämä Bash-skripti lähettää haaran muutokset Claudelle ja tulostaa löydetyt kirjoitusvirheet. Se kuuluu CI-työhön, GitHub Actionsin ajoympäristöön tai Git Bashiin. Tallenna nimellä typo-check.sh:

#!/usr/bin/env bash
set -euo pipefail

base="${1:-main}"
result=$(git diff "$base"...HEAD | claude -p \
  "Etsi kirjoitusvirheet tästä diffistä. Palauta jokaisesta rivi tiedosto:rivi ja virhe. Muuta ei." \
  --output-format json \
  --max-turns 3 \
  --max-budget-usd 0.50)

echo "$result" | jq -r '.result'
echo "arvioitu kulu: $(echo "$result" | jq -r '.total_cost_usd') USD" >&2
  • set -euo pipefail pysäyttää skriptin, jos jokin vaihe epäonnistuu. Epäonnistumista ei lasketa onnistumiseksi.
  • Diffi tulee putkea pitkin, joten Claude ei tarvitse oikeutta ajaa git-komentoja.
  • --max-turns rajoittaa askeleiden määrää ja --max-budget-usd arvioitua kulua dollareina. Molemmat toimivat vain -p-ajossa. Kulu on Clauden oma arvio ja voi poiketa laskusta, joten jätä rajan alle väljyyttä.
  • jq poimii tuloksen JSON-vastauksesta.

Windowsissa PowerShellissä sama toimii näin (lainausmerkit ovat PowerShellin sääntöjen mukaiset):

(git diff | claude -p "Etsi kirjoitusvirheet tästä diffistä. Palauta jokaisesta rivi tiedosto:rivi ja virhe. Muuta ei." --output-format json --max-turns 3 | ConvertFrom-Json).result

Turvallinen ajo: luvat, rajat ja kulut

Valvomaton ajo on vaarallisempi kuin keskustelu, koska kukaan ei huomaa virhettä ajoissa. Kolme sääntöä:

  • Anna vain tarvittavat työkalut. --allowedTools "Read" sallii pelkän lukemisen. Komennot rajataan kuvioilla: Bash(git diff *) sallii vain komennot, jotka alkavat git diff. Välilyönti ennen tähteä on tärkeä.
  • Valitse lupatila tehtävälle. --permission-mode acceptEdits hyväksyy tiedostomuutokset. --permission-mode dontAsk kieltää kaiken, mitä ei ole erikseen sallittu, ja sopii lukittuihin CI-ajoihin. Älä käytä bypassPermissions-tilaa tai valitsinta --dangerously-skip-permissions ajossa, jota kukaan ei valvo (moduulit 7 ja 12).
  • Aseta katot. --max-turns, --max-budget-usd ja CI-työn aikaraja (timeout-minutes GitHubissa, timeout GitLabissa) estävät, että virheellinen silmukka jää pyörimään.

Syötteet ovat epäluotettavaa dataa myös CI:ssä: pull requestin teksti, issue tai tiedosto voi sisältää ohjeita Claudelle. Pidä siksi valvomattoman työn työkalut niin kapeina, ettei onnistunut injektio pääse mihinkään (moduuli 12).

Modit headless-ajossa

Anthropicin ohjeen mukaan claude -p hakee ja lataa asennetut pluginit, hookit, MCP-palvelimet ja CLAUDE.md-tiedostot samalla tavalla kuin interaktiivinen istunto, ellet käytä valitsinta --bare. Modi on plugin, joten koneelle asennettu modi latautuu myös ilman --bare-valitsinta ajettuun claude -p -kutsuun. Headless-ajossa ei ole käyttöliittymää, joten tilarivi, toast ja kaista eivät näy kenellekään, eikä lupakysymykseen ole vastaajaa.

  • --bare ohittaa asennetut pluginit. Silloin modi ei lataudu, eikä sen tarkistusta tehdä lainkaan. Valitsimella --plugin-dir annetun pluginin hookit eivät aja bare-tilassa.
  • dontAsk ei sulje modeja pois. Ohjeen mukaan asentamasi modi voi silti hyväksyä osan kutsuista tässäkin tilassa.
  • GitHubin ja GitLabin ajoympäristö on puhdas kone. Siellä on vain ne modit, jotka työ itse asentaa.
reach-bandin toimintaa claude -p -ajossa ei ole testattu. Emme tiedä, mitä tason 3 kutsulle tapahtuu siellä: kysyykö se, estääkö se vai päästääkö se kutsun läpi. Älä luota siihen valvomattomassa ajossa. Käytä sen sijaan tiukkoja --allowedTools-rajauksia ja lupatilaa, --max-turns- ja --max-budget-usd-rajoja, aikarajaa ja kertakäyttöistä ajoympäristöä. reach-bandin tasot ja testatut ympäristöt: moduuli 13.

GitHub Actions

Anthropicin virallinen toiminto on anthropics/claude-code-action. Kun työnkulku antaa sille prompt-syötteen, se toimii automaatiotilassa: Claude ajetaan tapahtumasta (esimerkiksi ajastuksesta) ilman @claude-mainintaa, ja tulos näkyy työnkulun lokissa. Ilman prompt-syötettä se vastaa @claude-maininnoihin issuissa ja pull requesteissa.

Valmistelu: asenna Claude GitHub App repositorioon (tai aja /install-github-app Claude Codessa) ja tallenna API-avain repositorion salaisuutena nimellä ANTHROPIC_API_KEY. Tarvitset repositorion ylläpitäjän oikeudet.

Tiedosto .github/workflows/paivaraportti.yml tekee joka päivä klo 09.00 UTC yhteenvedon eilisistä commiteista ja avoimista issueista:

name: Päiväraportti
on:
  schedule:
    - cron: "0 9 * * *"
  workflow_dispatch:
jobs:
  report:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    permissions:
      contents: read
      issues: read
      id-token: write
    steps:
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: "Tee yhteenveto eilisen commiteista ja avoimista issueista"
          claude_args: |
            --max-turns 5
            --allowedTools "mcp__github__list_commits,mcp__github__list_issues"
  • ${{ secrets.ANTHROPIC_API_KEY }} on viittaus salaisuuteen. Avaimen arvoa ei kirjoiteta tiedostoon.
  • claude_args välittää Claude Coden valitsimet. --allowedTools antaa Claudelle vain kaksi GitHub-työkalua; ilman sitä pelkällä tekstikehotteella Claudella ei ole shell- eikä GitHub-yhteyttä.
  • timeout-minutes on työn aikaraja. workflow_dispatch antaa käynnistää työn käsin kokeilua varten.
  • GitHub ajaa ajastetut työnkulut vain oletushaarasta, ja julkisessa repositoriossa ajastus poistuu käytöstä 60 päivän jälkeen, jos repositoriossa ei ole toimintaa.
  • Toiminto torjuu botin käynnistämät ajot, ellei bottia ole listattu syötteeseen allowed_bots.

Ohjeet ja lisää esimerkkejä (muun muassa koodikatselmointi pull requestissa): Claude Code GitHub Actions.

GitLab CI

GitLab CI/CD -integraatio on Anthropicin ohjeessa vielä beeta-vaiheessa, ja sitä ylläpitää GitLab. Siinä ei ole omaa toimintoa: asennat Claude Coden ajoympäristöön ja kutsut samaa claude -p -komentoa. API-avain tallennetaan Settings → CI/CD → Variables -sivulla maskattuna muuttujana nimellä ANTHROPIC_API_KEY.

Tämä työ käy läpi merge requestin muutokset vain lukuoikeuksilla. Tiedosto .gitlab-ci.yml:

stages:
  - ai

mr-katselmointi:
  stage: ai
  image: node:24-alpine3.21
  timeout: 15m
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
  before_script:
    - apk add --no-cache git curl bash
    - curl -fsSL https://claude.ai/install.sh | bash
    - export PATH="$HOME/.local/bin:$PATH"
  script:
    - git fetch origin "$CI_MERGE_REQUEST_TARGET_BRANCH_NAME"
    - >
      git diff "origin/$CI_MERGE_REQUEST_TARGET_BRANCH_NAME"...HEAD |
      claude --bare -p "Katselmoi tämä diffi. Listaa virheet ja riskit lyhyesti."
      --allowedTools "Read"
      --max-turns 5
      --max-budget-usd 1.00
  • Asennusrivit ovat Anthropicin ohjeen mukaiset: asennin sijoittaa claude-komennon kansioon ~/.local/bin, joka ei ole tässä kuvassa polulla, siksi PATH asetetaan.
  • claude lukee avaimen ympäristömuuttujasta ANTHROPIC_API_KEY. --bare vaatii sen, koska se ei käytä tilauksen kirjautumista, ja pitää työn samanlaisena joka koneella.
  • Katot ovat samat kuin skriptissä: --max-turns, --max-budget-usd ja työn timeout.
  • Diffin muodostus (haaran haku ja vertailupiste) riippuu repositoriosi asetuksista. Kokeile ensin pienellä merge requestilla.

Ohjeet: Claude Code GitLab CI/CD. Valmis esimerkki mainintoihin vastaavasta työstä (@claude, GitLabin MCP-työkalut) ja Amazon Bedrock- ja Google Cloud -vaihtoehdot ovat siellä.

Ajastetut tehtävät ja /loop

Jos tehtävä toistuu, sitä ei tarvitse ajaa itse. Claude Codessa on kolme tapaa ajastaa:

Paikalliset tiedostotEi, tuore kloonausKylläKyllä

  • Pilvitehtävä (Anthropicin ohjeessa aiemmin "rutiini", routine) on tallennettu kehote, yksi tai useampi repositorio ja liitännät. Se on saatavilla Pro-, Max-, Ultra-, Team- ja Enterprise-tilauksilla, ja se on tutkimusjulkaisu, joten ominaisuus voi muuttua. Luo se komennolla /schedule tai osoitteessa claude.ai/code/routines, esimerkiksi /schedule daily PR review at 9am. Ajot kuluttavat tilauksesi käyttörajaa kuten tavalliset istunnot. Pilvessä istunto alkaa auto-tilassa, ja tehtävä toimii näkemänsä liitännöillä sinun nimissäsi, joten poista tarpeettomat liitännät.
  • /loop toistaa kehotetta istunnon sisällä, esimerkiksi /loop 5m check if the deployment finished and tell me what happened. Ilman väliä Claude valitsee sen itse. Toisto päättyy, kun istunto suljetaan, ja toistuva tehtävä vanhenee seitsemässä päivässä. Sopii lyhyeen seurantaan, ei pysyvään automaatioon.
  • Pysyvä ajastus CI:ssä: GitHub Actionsin schedule-liipaisin (yllä) ajaa työn ilman omaa konettasi.

Harjoitukset

1. Aja claude -p diffille

Edellyttää: Pro-tilaus, Claude Code ja git-repositorio, jossa on muutoksia. Ei Prota tai Claude Codea? Kopioi git diff -tuloste claude.ai-keskusteluun (Free) ja pyydä samaa tehtävää: kirjoitusvirheet muodossa tiedosto:rivi ja virhe.

Tee kertakäyttökansioon pieni muutos, jossa on tahallinen kirjoitusvirhe, ja aja osion "Skripti, joka kutsuu Claudea" PowerShell-rivi. Kuinka paljon ajo maksoi? Vaihda rivin lopussa .result muotoon .total_cost_usd ja aja uudelleen.

Näytä esimerkkivastaus

Tuloste on rivi muodossa tiedosto:rivi ja virhe, esimerkiksi README.md:3 "ymmärtää" kirjoitettu "ymmartää". JSON-vastauksesta saat lisäksi kentät session_id ja total_cost_usd; yhden pienen diffin arvioitu kulu on tyypillisesti sentin murto-osia. Jos -p-kutsu ei tulosta mitään, tarkista poistumiskoodi ($LASTEXITCODE) ja että olet kirjautunut. Puuttuva todennus tulostetaan tuloksena, ei poikkeuksena.

2. Aja ajastettu työ CI:ssä

Edellyttää: repositorio GitHubissa tai GitLabissa, ylläpitäjän oikeudet, API-avain organisaation luvalla sekä Claude GitHub App GitHubissa. Ei CI-oikeuksia tai avainta? Lue GitHub- ja GitLab-esimerkki ja vastaa paperilla tai claude.ai-keskustelussa (Free): mitä työkaluja Claudella on, mikä rajaa kulut ja mistä avain tulee.

Kopioi sopiva esimerkki repositorioosi, tallenna avain salaisuudeksi tai maskatuksi muuttujaksi ja käynnistä työ käsin (workflow_dispatch GitHubissa, Run pipeline GitLabissa). Vahvista lokista, että työ onnistui ja että se käytti vain sallittuja työkaluja.

Näytä esimerkkivastaus

GitHubissa tulos näkyy työnkulun ajon lokissa, ei kommenttina. Jos ajo epäonnistuu todennukseen, tarkista, että salaisuuden nimi on täsmälleen ANTHROPIC_API_KEY ja että työ sai sen (GitLabissa muuttuja voi olla suojattu haaralle, jolla ajat). Paperiversion vastaus: GitHub-työllä on kaksi GitHub-lukutyökalua (--allowedTools); kulun rajaavat --max-turns 5 ja timeout-minutes; avain tulee salaisuudesta secrets.ANTHROPIC_API_KEY. GitLab-työllä on vain Read; kulun rajaavat --max-turns, --max-budget-usd ja timeout; avain tulee maskatusta CI/CD-muuttujasta.

3. Tarkasta vaarallinen työ

Edellyttää: ei mitään; lukeminen ja lista riittävät, tai claude.ai (Free), jos haluat toisen mielipiteen.

Kollega ehdottaa tätä komentoa yön yli -ajoon, joka lukee uusia issueita sähköpostin ja verkkosivujen kanssa:

claude -p "Hoida kaikki uudet issuet" --dangerously-skip-permissions

Listaa, mitä puuttuu tai on vaarallista, ja korjaa komento.

Näytä esimerkkivastaus

Viat: (1) kaikki luvat ohitetaan, joten Claude voi ajaa mitä tahansa ilman kysymystä; (2) ei työkalurajausta; (3) ei --max-turns- eikä --max-budget-usd -rajaa, joten virhe voi syödä rahaa koko yön; (4) issuet ovat epäluotettavaa syötettä, ja injektio pääsisi käyttämään kaikkia oikeuksia (moduuli 12); (5) ei aikarajaa eikä kertakäyttöistä ympäristöä. Korjattu: claude -p "Tiivistä uudet issuet" --allowedTools "Read" --permission-mode dontAsk --max-turns 5 --max-budget-usd 1.00 kertakäyttöisessä ajoympäristössä, jolla on aikaraja. Mitä enemmän työ saa tehdä (kirjoittaa, ajaa komentoja), sitä tiukempi rajaus tarvitaan.

Lisä: rakenteinen tuloste, istunnot ja tarkistukset

  • Vastaus skeeman mukaan: --output-format json yhdessä valitsimen --json-schema kanssa palauttaa tuloksen kentässä structured_output. Tarkista, että kenttä on olemassa, ennen kuin skripti käyttää sitä: jos Claude kieltäytyi, sitä ei ole.
  • Jatka keskustelua: claude -p "..." --continue jatkaa viimeisintä keskustelua ja --resume tiettyä istuntoa session_id-tunnuksella.
  • Estä kysymykset kokonaan: --permission-prompts none (Claude Code 2.1.259 tai uudempi) kieltää kaiken, mikä muuten kysyisi, ellei hook tai modi salli kutsua, ja kertoo Claudelle, ettei kukaan voi hyväksyä pyyntöä.
  • Tarkista, että plugin latautui: --output-format stream-json -ajon system/init-tapahtuma listaa ladatut pluginit (plugins) ja latausvirheet (plugin_errors). CI voi epäonnistua, jos plugin puuttuu.
  • Plugin GitHub Actionissa: syötteet plugin_marketplaces ja plugins asentavat pluginin ennen ajoa. Valmis esimerkki on GitHub Actions -ohjeen kohdassa "Run a skill".
  • Ei tallennettua avainta: organisaatio voi käyttää työnkulun OIDC-tunnistetta (workload identity federation), jolloin repositoriossa ei ole pitkäikäistä salaisuutta. Ohje on GitHub Actions -sivun kohdassa "Set up for an organization".
  • Valmis katselmointi: jos et halua ylläpitää omaa työnkulkua, Anthropicin Code Review katselmoi pull requestit automaattisesti.
