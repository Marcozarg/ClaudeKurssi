Mitä tarvitset ja mitä et

Tässä moduulissa kerrotaan neljästä tavasta laajentaa Claude Codea: hookit, MCP-palvelimet, subagentit sekä omat skillit ja komennot. Sanotaan se suoraan: aloittelija ei tarvitse yhtäkään niistä. Moduulien 1-8 perusasiat riittävät pitkään, ja jokainen lisä on myös lisää ylläpidettävää ja lisää paikkoja, joissa jokin voi mennä pieleen.

Kokeile ensin ilman, ja lisää vasta kun huomaat tekeväsi samaa käsin kolmannen kerran. Sivun lopussa on valmiita Kopioitavia: asenna vain ne, joille tunnistat tarpeen.

Moduulin 9 Kopioitava coding-style on tämän sivun työkalujen perusta: align-style lukee sen. Katso asennus moduulista 9.

Jokaisen Kopioitavan taulukossa edellytykset on kirjoitettu englanniksi samoin kuin sen manifest.json-tiedostossa. Mistä ne saa: Claude Code moduulista 6, PowerShell 7 komennolla winget install Microsoft.PowerShell, Python 3 with pytest projektin omasta virtuaaliympäristöstä, Matt Pocock's skills plugin moduulista 9, OpenAI Codex CLI komennolla npm install -g @openai/codex ja plan-review- ja review-intake-komennot tältä sivulta.

Testattu: Claude Code 2.1.318, PowerShell 7.6.9, Python 3.14.7, Windows 11, marraskuu 2026 (11/2026). Muilla versioilla toiminta voi poiketa.

Hookit

Hook on komento, jonka Claude Code ajaa itse tietyssä kohdassa: esimerkiksi kun istunto alkaa (SessionStart), ennen työkalun käyttöä tai kun lähetät kehotteen. Hook ei ole pyyntö Claudelle vaan ohjelman suoritus, joka toimii aina samalla tavalla. Se sopii asioihin, joiden pitää tapahtua joka kerta: tarkistus, lokimerkintä, tilanteen tulostus.

Hookit asetetaan tiedostoon %USERPROFILE%\.claude\settings.json (kaikki projektit) tai projektin tiedostoon .claude\settings.json. Eri tasojen hookit yhdistyvät. SessionStart-hookin tulostama teksti lisätään Clauden kontekstiin, ja siksi sen pitää olla nopea.

Hook ajaa koodia koneellasi omilla oikeuksillasi. Lue jokainen hook ennen lisäämistä, kuten mikä tahansa komento.

Tämän sivun hookit ovat kahdessa Kopioitavassa: optimize-testsuite ja routing. Ne liitetään settings.json-tiedostoon käsin, koska tiedosto on henkilökohtainen eikä sitä kannata ylikirjoittaa.

Lähde: code.claude.com/docs/en/hooks

MCP-palvelimet

MCP (Model Context Protocol) on avoin standardi, jolla Claude kytketään ulkoisiin järjestelmiin: tehtävienseurantaan, tietokantaan, valvontaan tai rajapintaan. Kun palvelin on kytketty, Claude voi lukea ja toimia kohdejärjestelmässä suoraan sen sijaan, että liität tietoa keskusteluun.

Palvelin lisätään komennolla claude mcp add. Listan näet komennolla claude mcp list ja tilan istunnossa komennolla /mcp. Näkyvyys riippuu laajuudesta: paikallinen (vain sinä, tämä projekti), projekti (.mcp.json, jaetaan versionhallinnassa) tai käyttäjä (kaikki projektisi).

Kytke vain palvelimia, joihin luotat. Palvelin, joka hakee ulkoista sisältöä, voi altistaa Clauden kehotteen injektiolle (tekstille, joka yrittää ohjata sitä). Tarkista, mitä oikeuksia annat.

Usein pärjää ilman MCP:tä: Claude voi ajaa komentorivityökaluja (kuten gh, moduuli 8), ja moduulissa 5 näit claude.ai:n valmiit liitännät. MCP-palvelin kannattaa lisätä vasta, kun tarvitset järjestelmää, jolle ei ole komentorivityökalua.

Lähde: code.claude.com/docs/en/mcp

Subagentit

Subagentti on erikoistunut apulainen, jolle Claude antaa tehtävän. Sillä on oma ikkunansa, oma ohjeensa, omat työkalunsa ja usein eri malli. Hyöty: pitkä tulostus (hakutulokset, lokit) jää sivuun pääkeskustelusta, ja Claudelle palaa vain yhteenveto.

Subagentti on Markdown-tiedosto, jonka alussa on YAML-otsake: name, description (kertoo, milloin Claude käyttää sitä), tools ja model. Tiedosto tallennetaan kansioon %USERPROFILE%\.claude\agents\ (kaikki projektit) tai projektin kansioon .claude\agents\. Claude Codessa on myös valmiit subagentit, kuten Explore (nopea haku) ja Plan (suunnittelutilaan).

Oman subagentin teet alla kohdassa Oma subagentti. Kopioitava routing sisältää kolme valmista esimerkkiä, joista näet rakenteen.

Lähde: code.claude.com/docs/en/sub-agents

Skillit, komennot ja lisäosat

Skill on kansio, jonka sisällä on tiedosto SKILL.md. Claude lataa sen, kun se sopii tilanteeseen, tai kutsut sen itse kirjoittamalla /skillin-nimi. Henkilökohtainen skill on kansiossa %USERPROFILE%\.claude\skills\<nimi>\, projektin oma kansiossa .claude\skills\. Kansioon voi laittaa myös tukitiedostoja, kuten skriptejä.

Oma slash-komento on yksittäinen Markdown-tiedosto kansiossa %USERPROFILE%\.claude\commands\: tiedosto done-check.md luo komennon /done-check. Dokumentaation mukaan komennot on yhdistetty skilleihin: vanhat komentotiedostot toimivat edelleen, ja jos samalla nimellä on sekä skill että komento, skill voittaa. Uusille suositellaan skillejä. Tämän sivun komennot ovat yksittäisiä tiedostoja yksinkertaisuuden vuoksi.

Lisäosa (plugin) paketoi skillejä ja muita osia jaettavaksi. Lisäosan skillit nimetään muodossa /lisäosan-nimi:skillin-nimi, jotta ne eivät törmää omiisi. Hallinta tehdään komennolla /plugin.

Oma skill viidessä minuutissa

Kun pyydät samaa kolmatta kertaa, siitä kannattaa tehdä skill. Rakennetaan yksi harjoituskansiossa, jotta oma asetuksesi pysyy koskemattomana.

  1. Tee kansio ja avaa siinä Claude Code: mkdir harjoitus-skill, cd harjoitus-skill, claude.
  2. Pyydä Claudea tekemään skill: 
    Tee tähän projektiin skill nimeltä tikettivastaus kansioon .claude\skills\tikettivastaus\. Se kirjoittaa vastauksen loppukäyttäjän tikettiin tiimimme sävyllä: tervehdys etunimellä, syy yhdellä lauseella, korjaavat askeleet numeroituna ja lopetus. Kirjoita description niin, että siinä lukee, mitä skill tekee ja milloin sitä käytetään.
  3. Lue Clauden kirjoittama SKILL.md. Se näyttää suunnilleen tältä. Kaikki otsakekentät ovat vapaaehtoisia, mutta description kannattaa aina kirjoittaa, ja name on oletuksena kansion nimi: 
    ---
name: tikettivastaus
description: Kirjoittaa vastauksen loppukäyttäjän tikettiin tiimin sävyllä. Käytä, kun käyttäjä pyytää vastausta, viestiä tai kuittausta tikettiin tai loppukäyttäjälle.
---

Kirjoita vastaus tässä järjestyksessä:

1. Tervehdys käyttäjän etunimellä.
2. Syy yhdellä lauseella ilman teknistä jargonia.
3. Korjaavat askeleet numeroituna, enintään viisi.
4. Lopetus: "Jos ongelma jatkuu, vastaa tähän viestiin."
  4. Skills-kansio on uusi tässä istunnossa, joten kirjoita /reload-skills. Kirjoita sitten /skills tai kysy "Mitä skillejä on käytettävissä?" ja varmista, että tikettivastaus on listalla.
  5. Aloita uusi istunto: kirjoita /exit ja käynnistä claude uudelleen. Pyydä tavallisesti, ilman komentoa /tikettivastaus: "Asiakas Liisa kirjoitti tikettiin, ettei tulostin tulosta. Syy oli jumiin jäänyt tulostusjono. Kirjoita hänelle vastaus." Claude Code näyttää rivin Launching skill: tikettivastaus. Pyydä sitten jotain asiaan kuulumatonta, esimerkiksi "Paljonko on 17 kertaa 23?": riviä ei pitäisi tulla.
  6. Jos riviä ei tullut, lisää descriptioniin sanoja, joita sanot luonnostaan. Jos skill käynnistyy liian usein, tee descriptionista tarkempi. Uusi istunto huomaa muokkauksen itse. Samassa istunnossa, jossa kansio syntyi, kirjoita muokkauksen jälkeen /reload-skills, koska sitä kansiota ei seurata.
Kun skill on valmis, siirrä se kansioon %USERPROFILE%\.claude\skills\, jolloin se on käytössä kaikissa projekteissa. Jos sama nimi on sekä henkilökohtaisena että projektin skillinä, henkilökohtainen voittaa. Jos skillillä on sivuvaikutuksia (se lähettää, poistaa tai julkaisee jotain), lisää otsakkeeseen disable-model-invocation: true, jolloin se käynnistyy vain komennolla /nimi.

Lähde: code.claude.com/docs/en/skills, tarkistettu 11/2026.

Oma subagentti

Subagentin saa samalla tavalla: pyydä Claudea tekemään se harjoituskansioon.

Luo tähän projektiin subagentti nimeltä lokien-lukija kansioon .claude\agents\. Se etsii lokitiedostoista virheet ja niiden ajat eikä muuta tiedostoja. Anna sille vain työkalut Read, Grep ja Glob ja malli haiku.

Lue syntynyt tiedosto .claude\agents\lokien-lukija.md. Se näyttää suunnilleen tältä:

---
name: lokien-lukija
description: Etsii lokitiedostoista virheet ja niiden ajat. Käytä, kun pyydetään käymään lokit läpi.
tools: Read, Grep, Glob
model: haiku
---

Käy annetut lokitiedostot läpi. Listaa jokainen virhe, sen aika ja tiedosto. Älä muuta tiedostoja.

Pakolliset kentät ovat name ja description. Jos tools puuttuu, subagentti saa kaikki työkalut, joten lukijalle ja tarkastajalle annetaan vain lukutyökalut. Uudet ja muokatut tiedostot huomataan muutamassa sekunnissa, mutta kansiota .claude\agents\ ei ollut istunnon alkaessa, joten käynnistä Claude Code nyt uudelleen (/exit ja claude). Pyydä sitten Claudea tekemään harjoituskansioon pieni app.log, jossa on muutama virherivi.

Kutsu subagenttia kirjoittamalla @ ja valitsemalla se listasta, esimerkiksi @lokien-lukija käy app.log läpi, tai nimellä: "Käytä lokien-lukija-subagenttia käymään läpi app.log."

Lähde: code.claude.com/docs/en/sub-agents, tarkistettu 11/2026.

Mallireititys

Eri mallit maksavat eri verran. Haku, testien ajo ja selkeän tiketin toteutus eivät yleensä vaadi kalleinta mallia, kun taas suunnittelu, vaikea virheenetsintä ja lopputarkistus vaativat. Mallireititys tarkoittaa, että pääistunto pysyy suunnittelijana ja antaa sopivan työn halvemmalle agentille.

SubagenttiMalliTehtävä
scoutHaiku, matala työmääräHaku monesta tiedostosta; palauttaa polut ja rivinumerot
runnerHaiku, matala työmääräTestien ja buildien ajo; palauttaa virheet sellaisenaan
implementerSonnet, keskitasoYhden hyvin määritellyn tiketin toteutus testeineen

Komento /routing ohjaa kokonaisuutta:

  • /routing on: ottaa reitityksen käyttöön; tulostus sisältää säännön, jota Claude noudattaa istunnon loppuun.
  • /routing off: lopettaa delegoinnin tässä istunnossa.
  • /routing status: kertoo tilan yhdellä rivillä.
  • /routing report: näyttää kustannustaulukot ja kertoo, mikä erottuu.

SessionStart-hook tulostaa säännön uuden istunnon alussa vain, kun reititys on päällä. Kun se on pois, hook on hiljainen eikä lisää mitään kontekstiin. Reititys kannattaa vain silloin, kun subagentin malli on halvempi kuin istunnon malli: Sonnet-istunnossa implementer ei kannata, mutta Haiku-haku kannattaa yhä. Jos subagentin tulos ei läpäise tarkistusta, työ tehdään uudelleen ylemmällä tasolla ja ongelma kirjataan.

Lisä: kehotteet, skillien karsinta

Kehotteet ovat englanniksi, ja ne kopioidaan sellaisinaan. Ne auttavat pitämään skillit lyhyinä: turhat rivit pois ja päällekkäisyydet yhteen.

Kerätyt kehotteet, tekijä tuntematon; eivät kuulu kurssin CC BY 4.0 -lisenssiin.

Turhat rivit pois

Claude käy skillit läpi lause kerrallaan, poistaa lauseet, jotka Claude olisi tehnyt muutenkin, sekä etsii päällekkäiset skillit. Kehote muuttaa skillejä suoraan, joten tee ensin commit.

Audit my skills for no-op lines.
For every sentence, ask: would Claude have done that anyway? If yes, delete the whole sentence. Rewrite any "don't" line as what I want instead.
Then check which of my skills overlap. Show me which to condense into one or cut entirely.
End with a list of every sentence you deleted.

Kaksi tapaa löytää turhat rivit

Tarkka tapa ja aggressiivinen tapa. Tämä ei ole kehote vaan ohje sinulle.

Precise
Go line by line. Remove the line you suspect is a no-op. Run it again. And if the output didn't change, it was never doing anything in the first place.
Aggressive
(Which I personally prefer), is just have Claude scan the whole thing for no-op language and delete those words, then just see what happens.

Lyhennä skillit

Claude ehdottaa jokaiselle skillille lyhyemmän version ja merkitsee ne, jotka kannattaa tehdä vain itse kutsuttaviksi (disable-model-invocation: true). Mitään ei muuteta ennen hyväksyntääsi.

Simplify my existing skills.
For each one, propose a shorter version that keeps only the lines that change the output.
Then flag which skills are good candidates to make user-invoked only: ones I'd rather call myself than have you fire on your own. For those, set disable-model-invocation: true in the frontmatter.
Show me everything first. Apply only what I approve.

Lisä: kehotteet, vakiintuneet termit

Kun selität skillissä jotain alusta asti, vaikka asialla on jo vakiintunut nimi, voit lyhentää tekstiä käyttämällä nimeä.

Etsi puuttuvat termit

Claude käy skillit läpi, nimeää kohdat, joissa vakiintunut termi korvaisi selityksen ja järjestää ne säästyneiden rivien mukaan.

Audit my skills for missing leading words.
Find every place I explained something from scratch that already has an established framework or term.
For each one, quote my description, name the leading word that replaces it, and show how many lines it saves. Rank by lines saved.
Only suggest terms that really exist. If there isn't one, say so and leave it alone.

Yksittäisen asian nimi

Kysyy Claudelta, onko kuvaamallesi asialle vakiintunutta termiä tai viitekehystä.

Is there an established framework or term for what I'm describing?

Lisä: kehotteet, opi käytöstä

Skillit paranevat, kun niitä käytetään oikeassa työssä ja korjaukset kerätään keskusteluhistoriasta.

Kolmen vaiheen kierros

Tämä ei ole kehote vaan työtapa.

1. Run your skill on real work, not test cases.
2. Analyze chat history to fix recurring corrections.
3. Once you have that fix, stop and try again.

Toistuvat korjaukset

Claude käy läpi 30 päivän keskusteluhistorian, kokoaa kohdat, joissa korjasit Claudea ja järjestää ne skilliehdokkaiksi. Saman työn ja enemmän tekee Kopioitava retrospective.

Scan my conversation history from the past 30 days.
Flag every place I sent something back: where I corrected, redid, or re-explained what you gave me.
Group the repeats. For each one, show me my correction in my own words and the specific step of the process it happened in.
Rank which ones are candidates to become a skill.
Stop at the ranked list.

Skriptiksi sopivat vaiheet

Claude etsii skilleistä vaiheet, jotka voisi tehdä skriptinä, ja ehdottaa uusia skillejä keskusteluhistorian perusteella.

Analyze my project and identify and steps in my existing skills that can be programmatic scripts. Share those skills as well as how you'd migrate them to script optimized skills.
Review my entire conversation history to identify any additional skills I should create.

Lisä: kehotteet, setupin tarkistus, Codex ja mallit

Kehotteet asetusten siivoukseen, raskaan työn siirtoon Codexille ja halvimman riittävän mallin valintaan.

Setupin tarkistus

Claude käy läpi kontekstitiedostot ja merkitsee vanhentuneet tai keskenään ristiriitaiset kohdat. Mitään ei muuteta ennen hyväksyntääsi. Saman työn ja enemmän tekee Kopioitava align-style.

Review every contextual file I've got and flag anything that's gone stale: info that's outdated, or rules that conflict with each other.
For each one, tell me whether to update, merge, or delete it. Don't change anything until I sign off.

Codex raskaaseen työhön

Pyytää Claudea asentamaan Codex-lisäosan ja lisäämään CLAUDE.md:hen säännön, että raskas toteutustyö annetaan Codexille. Claude näyttää muutoksen ennen kirjoittamista. Asennuskomennot voit ajaa myös itse. Lisäosa on OpenAI:n virallinen (openai/codex-plugin-cc), ja asennus tehdään sen README:n mukaan.

Install the Codex plugin for Claude Code. Then add a rule to my CLAUDE.md: hand any token-heavy execution task to Codex instead of running it here — bulk file edits, well-specced builds, and bugs still failing after 2 tries. Show me the diff before writing.
  • Asennus: /plugin marketplace add openai/codex-plugin-cc, sitten /plugin install codex@openai-codex, sitten /reload-plugins.
  • Tarkistus: /codex:setup kertoo, onko Codex valmis. Jos Codex on asennettu mutta et ole kirjautunut, aja !codex login.
  • Vaatimukset: ChatGPT-tilaus (myös Free) tai OpenAI API -avain sekä Node.js 18.18 tai uudempi. Käyttö kuluttaa Codexin käyttörajoja.

Halvin riittävä malli

Claude käy skillit ja subagentit läpi ja ehdottaa kevyeltä työltä halvempaa mallia (haiku); ei muuta mitään. Sama ajatus on Kopioitava routing -mallireitityksessä.

Find the Minimum Viable Model for every skill in .claude/skills/ and subagent in .claude/agents/
Grunt work (scrape, summarize, classify, fetch, format) → model: haiku.
Judgment work (synthesize, decide, judge) → keep the top model.
Return a table: file → recommended change.
Don't change anything yet.

## Versioning rules

| Bump | When to use |
|---|---|
| `patch` | Bug fix, comment, typo, cosmetic, UX tweak that does not change behaviour |
| `minor` | Feature, behaviour change |
| `major` | Breaking change: API, protocol or file format |

If the bump type seems inconsistent with the description, say so before proceeding.

---

## Step 1 - Find the current version

Look for the version string in order of priority:
1. `package.json` -> `"version": "x.y.z"`
2. `pyproject.toml` -> `version = "x.y.z"`
3. A `VERSION` file containing only the semver string
4. A `__version__ = "x.y.z"` line in a `.py` file
5. A `<Version>x.y.z</Version>` element in a `.csproj`

If the project uses date versions or documents its own release procedure in CLAUDE.md, stop: that procedure applies.
If none is found, stop and ask the user where the version is defined.

Report: **Releasing `<project>` `<old>` -> `<new>`**

---

## Step 2 - Compute new version

Apply the bump:
- patch: increment Z (e.g. 1.2.3 -> 1.2.4)
- minor: increment Y, reset Z to 0 (e.g. 1.2.3 -> 1.3.0)
- major: increment X, reset Y and Z to 0 (e.g. 1.2.3 -> 2.0.0)

If the project uses a `V` prefix (e.g. `V2.3.1`), preserve it.

---

## Step 3 - Update the version source

Before editing, grep the repo for the old version string and update every other hard-coded copy of it too (docs, tests
that pin the version). Edit the file found in Step 1 to replace the old version string with the new one. That file is the
single source of truth - do not hardcode the version anywhere new.

---

## Step 4 - Update CHANGELOG.md

Find the project's `CHANGELOG.md` (it may sit next to the version source). Prepend a new entry immediately after the
first heading (or at the top if no heading exists), one line per change:

```
### Vx.y.z - YYYY-MM-DD
- <change>
- <change>
```

Use today's date. Do not modify existing entries.

---

## Step 5 - Commit and push

Stage only the files changed above (version source + CHANGELOG.md) plus the files of the change being released.
Never stage secrets.

```
git add <version-file> CHANGELOG.md
git commit -m "<Component> Vx.y.z: <summary of the changes>"
```

Push only when the user's rules (`~/.claude/coding-style.md` or the project's CLAUDE.md) say to push, and then only to
the project's own remote. Otherwise leave the commit local and say so. Commit and push are separate commands.

Leave out `<Component>` in a single-component project.

Report: old version -> new version, files changed, commit hash.

What this produces: a short report with counts and evidence, then a plan (questions to the user, independent ones in one round) for the skills,
hooks, agents, test changes and deletions that follow. Nothing is deleted or created without the plan being approved.

## 1. Mine the history (script)

```

```

`-Project` = the folder name under `~/.claude/projects/` (Claude Code names it after the project's path, with the separators
replaced by dashes). `-ProjectsDir` points the script at another projects folder. The script reads every
`*.jsonl` transcript newer than `-Days` and the memory folder, and writes a markdown report with:

- **Repeated commands by shape** (Bash/PowerShell calls with paths and numbers normalised): the top of this list is the skill or
  hook candidate; anything run by hand more than ~20 times is a script.
- **User corrections**: user messages containing "still", "again", "doesn't work", "don't want", "i dont", "broken", "wrong",
  "not what" - with the message text, so the pattern behind them can be named.
- **Review findings** pasted or produced by a reviewer (`[P1]`/`[P2]` lines) grouped by the category words in them (fail-open,
  compatibility, trust boundary, lifecycle, contract, race, UI, test).
- **Test runs**: every "N tests, N passed, N failed" summary and every pytest summary ("N passed, N failed in N s") with
  its duration; the most frequent failing test names (pytest's `FAILED tests/...::name` lines too).
- **Skill and tool usage**: which skills were invoked how often; plan edits and compaction counts.
- **Stale records**: memory files whose description says "pending"/"in progress" although a later memory records the outcome;
  memory lines pointing to plan files that no longer exist or hold a different plan (plan file names are reused per conversation);
  counts in memories that disagree with the repo (tests, versions).

## 2. Read with the questions

For each of the user's questions, answer from the counts, not from impressions:

- *Skills/agents*: what was done by hand repeatedly (top shapes), what needed the same reading every time (helper contracts, file
  ranges), what review classes kept coming back (an agent with that checklist).
- *Faster/more accurate methods*: what caused rework (encoding, whole-file reads and compactions, stale literal counts in tests,
  misread helpers), and the rule or hook that removes the class, not the instance.
- *Testing*: wall time and where it goes (sequential? database?), the tests that fail for reasons unrelated to the change, what is
  selected by memory instead of by impact.
- *Stale data*: memories superseded by docs, finished plans, snapshots and archives, settings text with old names, doc headers.

## 3. Plan it

Ask the user (independent questions in one round, recommendation first) about scope, where skills live, which
deletions are allowed, and the test-runner design. Before any deletion: a hash-verified zip of everything to be deleted plus an
inventory file, kept 30 days. Secrets (keys, ini files) never go into the zip. Then /plan-review, and implement.

# optimize-testsuite

What this produces: before/after medians of comparable full runs, each change with the gain it showed before it was applied, a
stability result and an accepted baseline. The project changes only on approval, one change at a time.

`ts` below is `& $HOME\.claude\skills\optimize-testsuite\testsuite.ps1`, called from PowerShell (a list such as
`-RunnerArgs @('-q', '-n', '12')`). It writes one report per run to `$HOME\.claude\test-suite-metrics\<hash of root>\`:
`<id>.summary.json`, `<id>.cases.json` (per test: outcome and setup, call, teardown seconds) and `<id>.log`. Nothing is written
into the project. A run is stopped at `-TimeoutSec`, else at the larger of the default (600 s) and three
times the median of the last three runs. `measure` stops at the first run that is not clean.

## 1. Baseline

Take the full-suite command from the project's CLAUDE.md and run it; measuring changes nothing in the project.

- pytest from `<root>\.venv`: `ts measure -Root <root> -RunnerArgs '-q' -Repeat 3` (`-RunnerArgs` = what the project writes after
  `pytest`; a partial run adds `-Selection focused`). Without that venv, pass `-Python <path to python.exe>`; the
  interpreter needs pytest.

Done when three runs are `completed` with exit 0 and `ts status -Root <root>` shows a recent median. A failed or timed-out run is
a finding: go to step 6. A run is never repeated to get a pass.

## 2. Find the cost

From the newest `cases.json`: seconds per phase, per file, and the twenty slowest tests. Decide which shape it is: a few slow
tests, or overhead times N (median setup per test times the number of tests). For pytest read
`$HOME\.claude\skills\optimize-testsuite\python.md` first. Done when the three largest costs are named with their seconds.

## 3. Prototype

Measure what each candidate would save with the project untouched (python.md: outside plugin, process split). Done when every
candidate has a measured gain or is dropped.

## 4. Change

One AskUserQuestion, multi-select: every candidate with its measured gain, the marked test that keeps running the real path, and
the effect on isolation. Apply and measure the chosen ones one at a time. Speed comes from setup, fixtures, waits and shutdown;
every test case stays unless the user approves its removal by name. Build it by the project's own rules.

## 5. Stability

`ts measure -Root <root> -RunnerArgs <the same as step 1> -Repeat 5`, then one run in shuffled order (python.md) with
`-Selection focused`, so it never mixes into the full runs. Done when all five are `completed` with exit 0 and the same number of
tests as the baseline or more. A hang, timeout or failure goes to step 6, and no gain is reported from a suite that is not stable:
faster setup changes timing and exposes races that were always there.

## 6. Defect found

Stop optimizing. Show the evidence: the failing output or the stack dump in `<id>.log`. Ask with AskUserQuestion:

- fix it now with a regression test in its own commit (recommended), then start again at step 1 for a new baseline;
- or record it and end: report the evidence, the before numbers and "stability not reached", without accept-baseline. Done when
  that report is given.

## 7. Report and baseline

A before/after table (median, range, number of tests, seconds per phase), every test id present before and absent after (expected:
none), and what was not measured (CI, other machines). In the same AskUserQuestion as the report, ask to accept the new baseline,
then `ts accept-baseline -Root <root>` (it prints its three source runs); `-AllowFewerTests` only for removals the user approved.
Done when `ts status -Root <root>` shows the baseline accepted in this run.

- A "Test-suite advisory" comes from the daily hook (`ts evaluate`), which only reads reports. It advises when the median of the

- Runs are comparable when the command, runner version, runtime and number of pytest-xdist workers match and the number of
  tests, and of skipped plus xfailed tests, differs by at most max(5, 5 percent). A run with no counted tests is not valid.
  `ts status -Root <root>` says why runs are not compared; a slow advisory says when the regression check is off.

# pytest: finding and proving the cost

Reference for steps 2, 3 and 5 of optimize-testsuite. `<py>` is `<root>\.venv\Scripts\python.exe`, run from `<root>`.

## Where the time goes

`cases.json` rows are `[nodeid, outcome, setup, call, teardown]`. Totals per phase, per file and the slowest tests:

```powershell
$c = Get-Content <id>.cases.json -Raw | ConvertFrom-Json
'setup {0:n1}  call {1:n1}  teardown {2:n1}' -f ($c | % { $_[2] } | measure -Sum).Sum, ($c | % { $_[3] } | measure -Sum).Sum, ($c | % { $_[4] } | measure -Sum).Sum
$c | group { ($_[0] -split '::')[0] } | % { [pscustomobject]@{ file = $_.Name; n = $_.Count; s = [math]::Round(($_.Group | % { $_[2] + $_[3] + $_[4] } | measure -Sum).Sum, 1) } } | sort s -Descending | select -First 10
$c | sort { $_[2] + $_[3] + $_[4] } -Descending | select -First 20 | % { '{0,6:n2}  {1}' -f ($_[2] + $_[3] + $_[4]), $_[0] }
```

A flat list with a median setup of a few hundredths of a second means overhead times N: look at what every test's fixture does
(app start, migrations, key derivation, client start), not at single tests.

## The profiler trap

cProfile charges the time of a generator fixture to the frames that span its `yield`, and sees only the main thread. In
one project it showed 20 s of teardown where the phase durations showed 1 s. Trust the phase seconds in `cases.json`, then time
the suspect alone in a ten-line script (create the app, start the client, log in, one request: each on its own).

## Measuring a gain with the project untouched

- **Outside plugin.** Put the shortcut in a module outside the repo and load it:
  `$env:PYTHONPATH = '<scratchpad>'; & <py> -m pytest -q -p my_shortcut`. The module patches what the change would patch (for
  example replaces a start function with one that copies a prepared database) and the run shows the saving before any approval.
  Tests that fail under the prototype show which ones need the real path.
- **Process split** estimates parallel gain without installing anything: split the test files over N processes
  (`Start-Process` per group, wait for all) and take the wall time. It also shows whether tests share ports or files.
- **Order check.** A module with `pytest_collection_modifyitems` that reverses or shuffles `items` (seeded), loaded with `-p`,
  shows order dependence. Run it before and after a change that touches fixtures.

## Hangs

`ts measure` runs with `faulthandler_timeout=45` and kills the process tree at its own timeout, so `<id>.log` holds the stack of
every thread at the moment a test sat for 45 s. A thread standing in application code under an event loop frame is spinning, not
waiting. The venv launcher starts a second `python.exe`; a kill by hand needs `taskkill /PID <pid> /T /F`.

Faster setup exposes races that were always there: a busy loop in a job-draining function (an
`await gather(...)` over tasks that had all ended never yields) became 2 hangs in 5 runs, first on the fourth; in
another project xdist exposed three tests reading state a background loop had not written yet. That is why step 5 repeats.

## What has worked

| Pattern | Real path kept by | Gain |
|---|---|---|
| Cheap test-only cost (scrypt at production cost twice per test, lowered by a fixture) | a `real_hash` test checks production parameters | 160 s -> 56 s |
| Prepared state copied per test (a once-per-session migrated database, not 21 ms of migration each) | startup and migration modules marked `fresh_database` | 55 s -> 42 s |
| Routes built once per run (FastAPI 0.142 rebuilds every route per new app, 0.45 ms each, seen as slow calls; patch `_EffectiveRouteContext.from_api_route` in conftest) | login tests marked `fresh_routes` | 41.5 s -> 27.3 s |
| Server shutdown polls: `serve_forever(poll_interval=0.01)` in test servers (default waits up to 0.5 s) | n/a | per server stop |
| pytest-xdist `addopts = "-n auto"` when there is no setup to cut; one file runs with `-n 0` (workers start in about 10 s) | n/a | 138 s -> 27 s on 12 threads |

The route cost was found by timing one page alone (10 ms against 1 ms for the others) and profiling that request.

## What costs more than it gives

- One app object shared across tests: needs a production change and puts shared state between tests.
- Folding parametrized cases into one test: saves setup, loses the failing case's name.
- pytest-xdist: the largest gain left once setup is lean, and a dependency plus a CI change. It is its own decision for the user.
- Windows takes about 2 s to refuse a connection to a closed local port; tests that need a refused connection cost that there.

##   testsuite.ps1 measure -Root <project> [-RunnerArgs '-q'] [-Repeat 3] [-TimeoutSec <auto>] [-Selection focused]
##   testsuite.ps1 status  -Root <project>          recent median, baseline and what was advised, per kind of run
##   testsuite.ps1 accept-baseline -Root <project> [-AllowFewerTests]
##   testsuite.ps1 evaluate                         the daily hook: cwd and event from stdin JSON, one advisory or nothing
## measure runs pytest from <project>\.venv.
## Exit 0 when every run completed and passed, 1 otherwise. Reports: <StateDir>\<hash of root>\<id>.summary.json,
## <id>.cases.json (one row per test) and <id>.log (the run's output).
[CmdletBinding()]
param(
    [Parameter(Position = 0)]
    [ValidateSet('measure', 'evaluate', 'accept-baseline', 'status')]
    [string]$Command = 'status',
    [string]$Root,
    [string[]]$RunnerArgs = @(),
    [ValidateSet('full', 'focused')][string]$Selection = 'full',
    [int]$Repeat = 1,
    [int]$TimeoutSec = 0,
    [string]$Python,
    [switch]$AllowFewerTests,
    [string]$Cwd,
    [string]$HookEvent,
    [datetime]$Now = [datetime]::UtcNow,
    [string]$StateDir = (Join-Path $HOME '.claude/test-suite-metrics')
)

$ErrorActionPreference = 'Stop'

$Schema = 1
$KeepRuns = 100
$DefaultTimeoutSec = @{ pytest = 600 }
$SlowSeconds = 60
$WorsePercent = 1.25
$WorseSeconds = 10
$RecentDays = 14
$CooldownDays = 7

function Write-Json([string]$Path, $Value) {
    $temp = "$Path.tmp"
    ConvertTo-Json -InputObject $Value -Depth 6 | Set-Content -LiteralPath $temp -Encoding utf8
    [System.IO.File]::Move($temp, $Path, $true)
}

function Read-Json([string]$Path) {
    try { Get-Content -LiteralPath $Path -Raw | ConvertFrom-Json -AsHashtable }
    catch { throw "Cannot read $Path (modified $((Get-Item -LiteralPath $Path).LastWriteTimeUtc.ToString('o'))): $($_.Exception.Message)" }
}

function Get-CanonicalRoot([string]$Path) {
    if (-not $Path) { throw '-Root is required.' }
    (Resolve-Path -LiteralPath $Path).ProviderPath.TrimEnd('\')
}

function Get-Roots {
    $path = Join-Path $StateDir 'roots.json'
    if (-not (Test-Path -LiteralPath $path)) { return @() }
    @(Read-Json $path)
}

function Find-Root([string]$CanonicalRoot) {
    Get-Roots | Where-Object { $_.root -eq $CanonicalRoot } | Select-Object -First 1
}

function Register-Root([string]$CanonicalRoot, [string]$Runner) {
    $known = Find-Root $CanonicalRoot
    if ($known) { return $known }
    $bytes = [System.Text.Encoding]::UTF8.GetBytes($CanonicalRoot.ToLowerInvariant())
    $hash = [System.Convert]::ToHexString([System.Security.Cryptography.SHA256]::HashData($bytes)).Substring(0, 16).ToLowerInvariant()
    $entry = [ordered]@{ root = $CanonicalRoot; hash = $hash; runner = $Runner; slowRule = $true }
    New-Item -ItemType Directory -Path $StateDir -Force | Out-Null
    Write-Json (Join-Path $StateDir 'roots.json') @(@(Get-Roots) + $entry)
    $entry
}

function Get-ProjectDir($Entry) {
    $dir = Join-Path $StateDir $Entry.hash
    New-Item -ItemType Directory -Path $dir -Force | Out-Null
    $dir
}

$Skipped =[System.Collections.Generic.HashSet[string]]::new()

function Get-Summaries([string]$ProjectDir) {
    @(Get-ChildItem -LiteralPath $ProjectDir -Filter *.summary.json | Sort-Object Name -Descending |
        Select-Object -First $KeepRuns | ForEach-Object {
            try {
                $s = Read-Json $_.FullName
                if ($s.schema -ne $Schema) { throw "Cannot read $($_.FullName): schema $($s.schema), this script reads schema $Schema." }
                $s
            }
            catch {
                if (-not $SkipUnreadable) { throw }
                if ($Skipped.Add($_.Exception.Message)) { Write-Host "skipped: $($_.Exception.Message)" }
            }
        })
}

function Test-Valid($Summary) {
    $counted = $Summary.passed + $Summary.failed + $Summary.skipped + $Summary.xfailed + $Summary.xpassed
    $Summary.status -eq 'completed' -and $Summary.exitCode -eq 0 -and $Summary.failed -eq 0 -and $Summary.errors -eq 0 -and
        $null -ne $Summary.wallSeconds -and $Summary.collected -gt 0 -and $Summary.collected -ge $counted
}

function Get-Median([double[]]$Values) {
    $sorted = @($Values | Sort-Object)
    $sorted[[int][Math]::Floor(($sorted.Count - 1) / 2)]
}

function Get-Tolerance([int]$A, [int]$B) {
    [Math]::Max(5, [int][Math]::Ceiling(0.05 * [Math]::Max($A, $B)))
}

function Remove-OldRuns([string]$ProjectDir) {
    $statePath = Join-Path $ProjectDir 'state.json'
    $keep = @()
    if (Test-Path -LiteralPath $statePath) {
        # Without a readable state the baseline runs are unknown, so nothing is pruned.
        try { $state = Read-Json $statePath } catch { return }
        $keep = @($state.baselines.Values | ForEach-Object { $_.ids })
    }
    $old = Get-ChildItem -LiteralPath $ProjectDir -Filter *.summary.json | Sort-Object Name -Descending |
        Where-Object { ($_.Name -replace '\.summary\.json$') -notin $keep } | Select-Object -Skip $KeepRuns
    foreach ($file in $old) {
        $id = $file.Name -replace '\.summary\.json$'
        Remove-Item -LiteralPath (Join-Path $ProjectDir "$id.summary.json"), (Join-Path $ProjectDir "$id.cases.json"),
            (Join-Path $ProjectDir "$id.log") -Force -ErrorAction SilentlyContinue
    }
}

function Get-Git([string]$CanonicalRoot) {
    $revision = & git -C $CanonicalRoot rev-parse --short HEAD 2>$null
    if ($LASTEXITCODE -ne 0) { return @{ revision = $null; dirtyFiles = $null } }
    @{ revision = "$revision"; dirtyFiles = @(& git -C $CanonicalRoot status --porcelain | Where-Object { $_ }).Count }
}

function Invoke-Child([string]$Exe, [string[]]$Arguments, [string]$WorkDir, [hashtable]$Environment, [int]$Seconds, [string]$LogPath) {
    $info = [System.Diagnostics.ProcessStartInfo]::new($Exe)
    foreach ($a in $Arguments) { $info.ArgumentList.Add($a) }
    $info.WorkingDirectory = $WorkDir
    $info.UseShellExecute = $false
    $info.RedirectStandardOutput = $true
    $info.RedirectStandardError = $true
    foreach ($name in $Environment.Keys) {
        if ($null -eq $Environment[$name]) { [void]$info.Environment.Remove($name) } else { $info.Environment[$name] = $Environment[$name] }
    }
    $clock = [System.Diagnostics.Stopwatch]::StartNew()
    $process = [System.Diagnostics.Process]::Start($info)
    $stdout = $process.StandardOutput.ReadToEndAsync()
    $stderr = $process.StandardError.ReadToEndAsync()
    $timedOut = -not $process.WaitForExit($Seconds * 1000)
    if ($timedOut) {
        # The venv launcher starts the real interpreter as a child, so the whole tree goes.
        & taskkill /PID $process.Id /T /F 2>&1 | Out-Null
        $process.WaitForExit()
    }
    $clock.Stop()
    Set-Content -LiteralPath $LogPath -Value ($stdout.Result + $stderr.Result) -Encoding utf8
    @{ timedOut = $timedOut; exitCode = $process.ExitCode; seconds = [Math]::Round($clock.Elapsed.TotalSeconds, 2) }
}

function New-Summary([string]$Id, [datetime]$StartedUtc, [string]$CanonicalRoot, [string]$Runner, [string[]]$Argv, [string]$RunSelection) {
    [ordered]@{
        schema = $Schema; id = $Id; startedUtc = $StartedUtc.ToString('yyyy-MM-ddTHH:mm:ss.fffZ', [cultureinfo]::InvariantCulture)
        root = $CanonicalRoot; runner = $Runner; runnerVersion = $null; runtime = $null; argv = $Argv; selection = $RunSelection
        membership = $null; collected = $null; passed = $null; failed = $null; skipped = $null; xfailed = $null; xpassed = $null
        errors = $null; status = 'not-started'; exitCode = $null; wallSeconds = $null; phases = $null; workers = $null
        revision = $null; dirtyFiles = $null; log = $null; timeoutSec = $null
    }
}

function Get-Timeout([string]$ProjectDir, [string]$Runner, [string]$RunSelection) {
    if ($TimeoutSec -gt 0) { return $TimeoutSec }
    # Earlier runs only raise the limit: they may come from another interpreter or a much smaller suite.
    $walls = @(Get-Summaries $ProjectDir | Where-Object { (Test-Valid $_) -and $_.runner -eq $Runner -and $_.selection -eq $RunSelection } |
        Select-Object -First 3 | ForEach-Object { [double]$_.wallSeconds })
    if ($walls.Count -lt 3) { return $DefaultTimeoutSec[$Runner] }
    [int][Math]::Max($DefaultTimeoutSec[$Runner], 3 * (Get-Median $walls))
}

function Assert-RunnerArgs {
    $joined = @($RunnerArgs | Where-Object { $_ -match "^'|^-\S*,-" })
    if ($joined) {
        throw "-RunnerArgs got $($joined -join ' ') as one argument: 'pwsh -File' hands a list over as one string. Call the script " +
            "from PowerShell instead: & testsuite.ps1 measure -Root <root> -RunnerArgs @('-q', '-n', '12')"
    }
}

function Measure-Pytest([string]$CanonicalRoot, $Entry) {
    $exe = if ($Python) { $Python } else { Join-Path $CanonicalRoot '.venv\Scripts\python.exe' }
    if (-not (Test-Path -LiteralPath $exe)) { throw "No Python interpreter at $exe; pass -Python." }
    $dir = Get-ProjectDir $Entry
    $started = [datetime]::UtcNow
    # Milliseconds keep the ids of one process in run order; the two random digits separate two processes.
    $id = '{0}{1}' -f $started.ToString('yyyyMMdd-HHmmss-fff'), [guid]::NewGuid().ToString('N').Substring(0, 2)
    $summary = New-Summary $id $started $CanonicalRoot 'pytest' (@('python', '-m', 'pytest') + $RunnerArgs) $Selection
    $summary.log = "$id.log"
    $n = [Array]::IndexOf($RunnerArgs, '-n')
    if ($n -ge 0 -and $n + 1 -lt $RunnerArgs.Count) { $summary.workers = $RunnerArgs[$n + 1] }
    $git = Get-Git $CanonicalRoot
    $summary.revision = $git.revision
    $summary.dirtyFiles = $git.dirtyFiles

    $out = Join-Path $dir $id
    $arguments = @('-m', 'pytest') + $RunnerArgs + @('-p', 'tsm_report', '-o', 'faulthandler_timeout=45')
    $environment = @{ TSM_OUT = $out; PYTHONUNBUFFERED = '1'
                      PYTHONPATH = (@($PSScriptRoot, $env:PYTHONPATH) | Where-Object { $_ }) -join ';' }
    $summary.timeoutSec = Get-Timeout $dir 'pytest' $Selection
    $run = Invoke-Child $exe $arguments $CanonicalRoot $environment $summary.timeoutSec (Join-Path $dir "$id.log")

    $pluginPath = "$out.plugin.json"
    if ($run.timedOut) {
        $summary.status = 'timeout'
    }
    elseif (Test-Path -LiteralPath $pluginPath) {
        $plugin = Read-Json $pluginPath
        $summary.status = 'completed'
        $summary.wallSeconds = $run.seconds
        foreach ($name in 'runnerVersion', 'runtime', 'membership', 'collected', 'phases', 'workers') { $summary[$name] = $plugin[$name] }
        foreach ($name in 'passed', 'failed', 'skipped', 'xfailed', 'xpassed') { $summary[$name] = $plugin.counts[$name] }
        $summary.errors = $plugin.counts.error
    }
    if (-not $run.timedOut) { $summary.exitCode = $run.exitCode }
    Remove-Item -LiteralPath $pluginPath -Force -ErrorAction SilentlyContinue
    Write-Json "$out.summary.json" $summary
    $summary
}

function Get-Key($Summary) {
    @($Summary.runner, $Summary.runnerVersion, $Summary.runtime, ($Summary.argv -join ' '), $Summary.workers, $Summary.selection) -join '|'
}

function ConvertTo-Utc($Value) {
    if ($Value -is [datetime]) { return $Value.ToUniversalTime() }
    [datetime]::Parse($Value, [cultureinfo]::InvariantCulture, [System.Globalization.DateTimeStyles]::RoundtripKind).ToUniversalTime()
}

function Get-Day([datetime]$Utc) {
    $Utc.ToLocalTime().ToString('yyyy-MM-dd')
}

function Format-Seconds([double]$Value) {
    if ($Value -eq [Math]::Round($Value)) { "$([int]$Value) s" } else { "$([Math]::Round($Value, 1)) s" }
}

function Format-Tests($Runs) {
    $counts = @($Runs | ForEach-Object { [int]$_.collected } | Sort-Object)
    if ($counts[0] -eq $counts[-1]) { "$($counts[0]) tests" } else { "$($counts[0])-$($counts[-1]) tests" }
}

function Test-Comparable($A, $B) {
    if ((Get-Key $A) -ne (Get-Key $B)) { return $false }
    if ($A.membership -eq $B.membership) { return $true }
    $tolerance = Get-Tolerance $A.collected $B.collected
    [Math]::Abs($A.collected - $B.collected) -le $tolerance -and
        [Math]::Abs(($A.skipped + $A.xfailed) - ($B.skipped + $B.xfailed)) -le $tolerance
}

function Test-Trio($Runs) {
    (Test-Comparable $Runs[0] $Runs[1]) -and (Test-Comparable $Runs[0] $Runs[2]) -and (Test-Comparable $Runs[1] $Runs[2])
}

function New-Baseline($Runs, [string]$By, [string]$Day) {
    [ordered]@{
        ids = @($Runs | ForEach-Object { $_.id })
        median = Get-Median ($Runs | ForEach-Object { [double]$_.wallSeconds })
        collected = [int](Get-Median ($Runs | ForEach-Object { [double]$_.collected }))
        skipped = [int](Get-Median ($Runs | ForEach-Object { [double]($_.skipped + $_.xfailed) }))
        runsUntil = Get-Day (ConvertTo-Utc $Runs[2].startedUtc); setOn = $Day; by = $By
    }
}

function Read-State([string]$ProjectDir, $Entry) {
    $path = Join-Path $ProjectDir 'state.json'
    if (-not (Test-Path -LiteralPath $path)) {
        return @{ schema = $Schema; root = $Entry.root; evaluatedDay = $null; baselines = @{}; advised = @{} }
    }
    $state = Read-Json $path
    if ($state.schema -ne $Schema) { throw "Cannot read ${path}: schema $($state.schema), this script reads schema $Schema." }
    foreach ($name in 'baselines', 'advised') { if ($null -eq $state[$name]) { $state[$name] = @{} } }
    $state
}

function Get-Standing($Entry, $State, [datetime]$NowUtc) {
    # One record per kind of full run: what the recent runs say against the baseline.
    $runs = @(Get-Summaries (Join-Path $StateDir $Entry.hash) | Where-Object { $_.selection -ne 'focused' } |
        Sort-Object { ConvertTo-Utc $_.startedUtc })
    foreach ($group in $runs | Group-Object { Get-Key $_ }) {
        $valid = @($group.Group | Where-Object { Test-Valid $_ })
        $baseline = $State.baselines[$group.Name]
        for ($i = 0; -not $baseline -and $i + 2 -lt $valid.Count; $i++) {
            if (Test-Trio $valid[$i..($i + 2)]) { $baseline = New-Baseline $valid[$i..($i + 2)] 'first-trio' (Get-Day $NowUtc) }
        }
        $standing = @{ key = $group.Name; selection = $group.Group[0].selection; runner = $group.Group[0].runner; runs = $valid.Count
                       baseline = $baseline; recent = $null; median = $null; note = $null; reasons = @() }
        $last = @($valid | Select-Object -Last 3)
        if ($last.Count -lt 3) {
            $standing.note = 'three completed runs are needed'
        }
        elseif (($NowUtc - (ConvertTo-Utc $last[0].startedUtc)).TotalDays -gt $RecentDays) {
            $standing.note = "no three runs in the last $RecentDays days"
        }
        elseif (-not (Test-Trio $last)) {
            $standing.note = "the last three runs are not comparable: $(Format-Tests $last)"
        }
        else {
            $standing.recent = $last
            $standing.median = Get-Median ($last | ForEach-Object { [double]$_.wallSeconds })
            if ($Entry.slowRule -and $standing.median -gt $SlowSeconds) { $standing.reasons = @('slow') }
            if ($baseline) {
                $collected = [int](Get-Median ($last | ForEach-Object { [double]$_.collected }))
                $skipped = [int](Get-Median ($last | ForEach-Object { [double]($_.skipped + $_.xfailed) }))
                $tolerance = Get-Tolerance $collected $baseline.collected
                if ([Math]::Abs($collected - $baseline.collected) -gt $tolerance -or [Math]::Abs($skipped - $baseline.skipped) -gt $tolerance) {
                    $standing.note = "the baseline of $($baseline.collected) tests is no longer comparable; accept a new one"
                }
                elseif ($standing.median -gt $WorsePercent * $baseline.median -and $standing.median - $baseline.median -gt $WorseSeconds) {
                    $standing.reasons = @('regression') + $standing.reasons
                }
            }
        }
        $standing
    }
}

function Select-Advisory($Entry, $State, $Standings, [string]$Today) {
    $candidates = foreach ($standing in $Standings) {
        foreach ($reason in $standing.reasons) {
            $last = if ($State.advised[$standing.key]) { $State.advised[$standing.key][$reason] }
            $again = $last -and $standing.median -gt $WorsePercent * $last.median -and $standing.median - $last.median -gt $WorseSeconds -and
                ([datetime]$Today - [datetime]"$($last.day)").TotalDays -ge $CooldownDays
            if (-not $last -or $again) { @{ standing = $standing; reason = $reason } }
        }
    }
    $chosen = @($candidates) | Sort-Object { $_.reason -ne 'regression' }, { -$_.standing.median } | Select-Object -First 1
    if (-not $chosen) { return $null }
    $standing = $chosen.standing
    if (-not $State.advised[$standing.key]) { $State.advised[$standing.key] = @{} }
    $State.advised[$standing.key][$chosen.reason] = @{ day = $Today; median = $standing.median }

    $name = Split-Path -Leaf $Entry.root
    $runs = "the median of the last three comparable $($standing.selection) runs is $(Format-Seconds $standing.median)"
    $span = "$(Format-Tests $standing.recent), $(Get-Day (ConvertTo-Utc $standing.recent[0].startedUtc)) to $(Get-Day (ConvertTo-Utc $standing.recent[2].startedUtc))"
    $finding = if ($chosen.reason -eq 'regression') {
        $over = $standing.median - $standing.baseline.median
        "regression: $runs, $(Format-Seconds $over) ($([int](100 * $over / $standing.baseline.median)) %) over the baseline of " +
            "$(Format-Seconds $standing.baseline.median) from $($standing.baseline.runsUntil) ($span)."
    }
    else {
        $off = if ($standing.note) { " Regression check off: $($standing.note)." } else { '' }
        "slow suite: $runs ($span), over the $SlowSeconds s mark.$off"
    }
    $text = "Test-suite advisory for ${name}: $finding In your next reply add one brief suggestion to run /optimize-testsuite " +
        'for this project; do not start it unasked.'
    $text.Substring(0, [Math]::Min($text.Length, 600))
}

function Find-RootOf([string]$Path) {
    $path = $Path.Replace('/', '\').TrimEnd('\')
    Get-Roots | Where-Object { $path -eq $_.root -or $path.StartsWith("$($_.root)\", [System.StringComparison]::OrdinalIgnoreCase) } |
        Sort-Object { $_.root.Length } -Descending | Select-Object -First 1
}

function Format-Run($Summary) {
    $tests = if ($null -ne $Summary.collected) { "$($Summary.collected) tests" } else { 'tests unknown' }
    $wall = if ($null -ne $Summary.wallSeconds) { "$($Summary.wallSeconds) s" } else { 'no wall time' }
    $failures = if ($Summary.failed -or $Summary.errors) { "  $($Summary.failed) failed, $($Summary.errors) errors" } else { '' }
    "$($Summary.id)  $($Summary.status)  $tests  $wall  exit $($Summary.exitCode)$failures"
}

$SkipUnreadable = $Command -in 'measure', 'status', 'accept-baseline'

switch ($Command) {
    'measure' {
        Assert-RunnerArgs
        $canonical = Get-CanonicalRoot $Root
        $known = Find-Root $canonical
        $entry = if ($known) { $known } else { Register-Root $canonical 'pytest' }
        $bad = 0
        foreach ($i in 1..$Repeat) {
            $summary = Measure-Pytest $canonical $entry
            Format-Run $summary
            if (-not (Test-Valid $summary)) {
                $bad++
                "  not a clean run; output: $(Join-Path (Get-ProjectDir $entry) $summary.log)"
                if ($i -lt $Repeat) { "  stopped: $($Repeat - $i) repeat(s) not run" }
                break
            }
        }
        Remove-OldRuns (Get-ProjectDir $entry)
        if ($bad -gt 0) { exit 1 }
    }
    'status' {
        $canonical = Get-CanonicalRoot $Root
        $entry = Find-Root $canonical
        if (-not $entry) { throw "$canonical has no measurements; run measure first." }
        $dir = Get-ProjectDir $entry
        $state = Read-State $dir $entry
        $standings = @(Get-Standing $entry $state $Now.ToUniversalTime())
        if (-not $standings) { "no full runs measured for $canonical" }
        foreach ($standing in $standings) {
            $recent = if ($standing.recent) { "recent median $(Format-Seconds $standing.median) over $(Format-Tests $standing.recent)" } else { $standing.note }
            $b = $standing.baseline
            $baseline = if ($b) { "baseline $(Format-Seconds $b.median) over $($b.collected) tests from $($b.runsUntil) ($($b.by))" } else { 'no baseline' }
            $note = if ($standing.recent -and $standing.note) { "; $($standing.note)" } else { '' }
            $advised = if ($state.advised[$standing.key]) {
                '; advised: ' + (($state.advised[$standing.key].GetEnumerator() | ForEach-Object { "$($_.Key) $($_.Value.day) at $(Format-Seconds $_.Value.median)" }) -join ', ')
            } else { '' }
            "$($standing.selection) ($($standing.runner)): $($standing.runs) completed run(s); $recent; $baseline$note$advised"
        }
        "evaluated: $(if ($state.evaluatedDay) { $state.evaluatedDay } else { 'never' })"
    }
    'accept-baseline' {
        if ($Selection -eq 'focused') { throw 'A baseline is kept for full runs only.' }
        $canonical = Get-CanonicalRoot $Root
        $entry = Find-Root $canonical
        if (-not $entry) { throw "$canonical has no measurements; run measure first." }
        $dir = Get-ProjectDir $entry
        $state = Read-State $dir $entry
        $last = @(Get-Summaries $dir | Where-Object { (Test-Valid $_) -and $_.selection -eq $Selection } |
            Sort-Object { ConvertTo-Utc $_.startedUtc } | Select-Object -Last 3)
        if ($last.Count -lt 3 -or -not (Test-Trio $last)) {
            throw "accept-baseline needs three comparable completed $Selection runs as the newest ones; see status."
        }
        $key = Get-Key $last[2]
        $new = New-Baseline $last 'accepted' (Get-Day $Now.ToUniversalTime())
        $old = $state.baselines[$key]
        if ($old -and $new.collected -lt $old.collected -and -not $AllowFewerTests) {
            throw "The newest runs hold $($new.collected) tests and the baseline $($old.collected). Name the tests that are gone; when they were removed on purpose, repeat with -AllowFewerTests."
        }
        $state.baselines[$key] = $new
        # Kept as advised at the accepted median, so the slow rule speaks again only when the suite gets materially worse.
        if (-not $state.advised[$key]) { $state.advised[$key] = @{} }
        $state.advised[$key].Remove('regression')
        $state.advised[$key]['slow'] = @{ day = $new.setOn; median = $new.median }
        Write-Json (Join-Path $dir 'state.json') $state
        "baseline for $Selection runs: $(Format-Seconds $new.median) over $($new.collected) tests (accepted $($new.setOn))"
        "from runs: $($new.ids -join ', ')"
    }
    'evaluate' {
        # The daily hook. It reads reports and the state; it never starts a run.
        $nowUtc = $Now.ToUniversalTime()
        $dir = $null
        try {
            if (-not $Cwd) {
                $raw = if ([Console]::IsInputRedirected) { [Console]::In.ReadToEnd() } else { '' }
                $hook = @{}
                if ($raw.Trim()) {
                    try { $hook = $raw | ConvertFrom-Json -AsHashtable } catch { throw "stdin is not JSON: $($_.Exception.Message)" }
                }
                $Cwd = $hook.cwd
                if (-not $HookEvent) { $HookEvent = $hook.hook_event_name }
            }
            if (-not $Cwd) { throw 'no cwd in stdin.' }
            $entry = Find-RootOf $Cwd
            if (-not $entry) { exit 0 }
            $dir = Join-Path $StateDir $entry.hash
            if (-not (Test-Path -LiteralPath $dir)) { exit 0 }
            $today = Get-Day $nowUtc
            $state = Read-State $dir $entry
            if ($state.evaluatedDay -eq $today) { exit 0 }
            $standings = @(Get-Standing $entry $state $nowUtc)
            foreach ($standing in $standings) {
                if ($standing.baseline -and -not $state.baselines[$standing.key]) { $state.baselines[$standing.key] = $standing.baseline }
            }
            $advice = Select-Advisory $entry $state $standings $today
            $state.evaluatedDay = $today
            Write-Json (Join-Path $dir 'state.json') $state
            if ($advice) {
                $event = if ($HookEvent) { $HookEvent } else { 'UserPromptSubmit' }
                @{ hookSpecificOutput = @{ hookEventName = $event; additionalContext = $advice } } | ConvertTo-Json -Compress -Depth 4
            }
        }
        catch {
            $message = $_.Exception.Message
            $where = if ($dir -and (Test-Path -LiteralPath $dir)) { $dir } else { $StateDir }
            $notePath = Join-Path $where 'diagnostic.json'

import hashlib
import json
import os
import platform

import pytest

PHASES = ("setup", "call", "teardown")


class Report:
    def __init__(self, out: str):
        self.out = out
        self.ids: list[str] = []
        self.cases: dict[str, dict] = {}

    def pytest_collection_finish(self, session):
        self.ids = sorted(item.nodeid for item in session.items)

    # Under pytest-xdist the controller collects nothing itself; each worker reports the ids it collected.
    @pytest.hookimpl(optionalhook=True)
    def pytest_xdist_node_collection_finished(self, node, ids):
        self.ids = sorted(ids)

    def pytest_runtest_logreport(self, report):
        case = self.cases.setdefault(report.nodeid, {"outcome": None, **dict.fromkeys(PHASES)})
        case[report.when] = round(report.duration, 4)
        if hasattr(report, "wasxfail"):
            if report.skipped:
                case["outcome"] = "xfailed"
            elif report.passed and report.when == "call":
                case["outcome"] = "xpassed"
        elif report.failed:
            # A failure outside the test body is pytest's "error", and it outranks a passed call.
            case["outcome"] = "failed" if report.when == "call" else "error"
        elif report.skipped:
            case["outcome"] = "skipped"
        elif report.when == "call" and case["outcome"] is None:
            case["outcome"] = "passed"

    def pytest_sessionfinish(self, session, exitstatus):
        if hasattr(session.config, "workerinput"):
            return
        counts = dict.fromkeys(("passed", "failed", "skipped", "xfailed", "xpassed", "error"), 0)
        for case in self.cases.values():
            if case["outcome"] is not None:
                counts[case["outcome"]] += 1
        phases = {p: round(sum(c[p] or 0 for c in self.cases.values()), 3) for p in PHASES}
        with open(self.out + ".cases.json", "w", encoding="utf-8") as f:
            json.dump([[nodeid, c["outcome"], *(c[p] for p in PHASES)] for nodeid, c in sorted(self.cases.items())], f)
        with open(self.out + ".plugin.json", "w", encoding="utf-8") as f:
            json.dump({"collected": len(self.ids),
                       "membership": hashlib.sha256("\n".join(self.ids).encode()).hexdigest(),
                       "counts": counts, "phases": phases, "runnerVersion": pytest.__version__,
                       "workers": str(workers) if (workers := getattr(session.config.option, "numprocesses", None)) else None,
                       "runtime": platform.python_version()}, f)

    ($T.in * $Price.input + $T.out * $Price.output + $T.read * $Price.cacheRead +

function Read-Usage([System.IO.FileInfo]$File) {
    # One API response is written as several lines carrying the same usage; keep the last per message id.
    $messages = [ordered]@{}
    $n = 0
    # ReadWrite share: a running session keeps its transcript open for writing.
    $reader = [System.IO.StreamReader]::new([System.IO.FileStream]::new($File.FullName, 'Open', 'Read', 'ReadWrite'))
    try {
        while ($null -ne ($line = $reader.ReadLine())) {
            $n++
            if (-not $line.Contains('"usage"')) { continue }
            try { $d = $line | ConvertFrom-Json }
            catch { throw "Cannot parse $($File.FullName) line ${n}: $($_.Exception.Message)" }
            if ($d.type -ne 'assistant' -or -not $d.message.usage) { continue }
            if ($d.message.model -eq '<synthetic>') { continue }
            $id = if ($d.message.id) { $d.message.id } else { $d.uuid }
            $messages[$id] = $d
        }
    }
    finally { $reader.Dispose() }
    $messages
}

    ''
}

# Model routing (on)

You stay the planner; hand suitable work to a cheaper agent when that costs less than doing it inline.
Delegation pays only while the agent's model is cheaper than the session's: in a session on Sonnet, skip `implementer`
and the `model: sonnet` overrides; `scout` and `runner` on Haiku still pay.

| Agent | Model / effort | Delegate |
|---|---|---|
| `scout` | Haiku / low | A search across many files or an unknown location. It returns paths and line numbers. |
| `runner` | Haiku / low | Running tests, builds or checks whose output is long. It returns failures verbatim. |
| `implementer` | Sonnet / medium | One well-specified ticket with its tests. Brief it with the goal, the files, the acceptance check and what is ruled out. |

Reviewers a skill starts as sub-agents (the Standards and Spec reviewers of `mattpocock-skills:code-review`) run with `model: sonnet`.
You aggregate their reports.

## With mattpocock skills

| Skill step | Route |
|---|---|
| `implement`, a ticket with nothing left to ask the user and its seams and files given by the ticket or by existing code (a page from an approved mockup, a new parser label) | `implementer` does the whole test-first loop. Brief it with the ticket text, the files, the seams, the test command, the answers the user already gave and what is ruled out. |
| `implement`, any other ticket; `diagnosing-bugs` | Main session. Ask the user first; a ticket that becomes mechanical after the answers may then go to `implementer`. |
| A fact from the code for `grilling`, `to-spec`, `to-tickets`, `triage` or plan mode | `scout`. Where plan mode requires `Explore`, start it with `model: haiku`. |
| The background agent of `research`; the codebase walk of `improve-codebase-architecture` | `model: sonnet`. |
| The design-it-twice agents of `codebase-design`; the `Plan` agent | Main model. |

After `implementer` returns, nothing is committed yet. Check its diff and that a new test fails without its change.
Then run `mattpocock-skills:code-review` on the working tree: give both reviewers the ticket and the whole change against the commit
the work started from, added files included (`git status --short`, `git diff <start>`, and each new file), since
`git diff <start>...HEAD` is empty before the commit. Then run your own final check of the change, and commit only when the user has asked.

## Everything else

The table above decides for the skill steps it names. For anything else, stay inline when the work is a few tool
calls or a lookup whose place you already know.
Planning, grilling, design, hard debugging, an inline review and the final check always stay in the main session.

Check every delegated result before using it. When it fails the check:

1. Redo it once, one tier up: `scout` or `runner` again with `model: sonnet`; a failed `implementer` ticket or reviewer report you finish yourself.
2. Say in the reply that it was escalated.
3. Log it:
   `pwsh -NoProfile -File "$HOME/.claude/routing/routing.ps1" log -Agent <agent> -Model <model> -Task "<what was asked>" -Problem "<what went wrong>"`

The user turns this off with `/routing off`; from then on none of this applies in the session.
