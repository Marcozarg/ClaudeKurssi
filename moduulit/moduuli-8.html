Git ja GitHub / GitLab

Ydin ~45 minLisä ~20 minPro / Max

Miksi git?

Git tallentaa tiedostojesi historian: voit palata aiempaan versioon, verrata muutoksia ja työskennellä turvallisesti rinnakkain. Claude voi tehdä paljon muutoksia nopeasti, joten git on turvaverkkosi. Moduulissa 7 näit, ettei /rewind seuraa shell-komentojen muutoksia. Git seuraa kaikkea, mikä on tallennettu.

Git on koneellasi oleva työkalu. GitHub ja GitLab ovat palveluja, joihin repo (koodivarasto) voidaan tallentaa ja joissa työtä seurataan issueilla ja muutospyynnöillä.

Tarvitset Git for Windowsin (git --version toimii terminaalissa). Jos ei toimi, asenna se osoitteesta git-scm.com ja avaa uusi terminaali.

Näin Claude Code käyttää gitiä

Claude Code ajaa git-komentoja samalla tavalla kuin muutkin komennot ja kysyy luvan, ellet ole sallinut niitä. Lukevat komennot (esimerkiksi git status ja git diff) sujuvat yleensä ilman kysymystä.

  • Muutosten katselu: "Mitä olen muuttanut? Kerro suomeksi." Claude lukee diffin ja tiivistää sen.
  • Commit-viestit: "Tee commit viestillä, joka kuvaa muutoksen." Claude tarkistaa muutokset, valitsee tiedostot ja kirjoittaa viestin.
  • Haarat: "Luo uusi haara tälle korjaukselle ja tee muutos siellä."
  • Konfliktit: "Auta selvittämään tämä yhdistämiskonflikti."
Tarkista aina diff ennen committia, ja pyydä pushia vain, kun olet valmis. Pidä pysyvät sallinnat (moduuli 7) tarkoituksella suppeina: git push ja git reset --hard eivät kuulu "allow always" -listalle. Älä committaa salaisuuksia (.env, salasanat, avaimet).

GitHub ja GitLab rinnakkain

Moduulissa 5 yhdistit GitHubin claude.ai:hin: se vain lukee tiedostoja eikä näe issueita tai pull requesteja. Claude Codessa asia on toisin: koska Claude voi ajaa komentoja, se voi käyttää palvelun komentorivityökalua ja työskennellä issueiden kanssa.

Esimerkkikehotteita

Kirjaudu ensin (gh auth login tai glab auth login) ja käynnistä claude repon kansiossa.

Listaa avoimet issuet ja ryhmittele ne aiheen mukaan. Kerro, mitkä näyttävät kiireellisimmiltä.
Luo issue: "Varmuuskopioskripti ei kirjaa virheitä lokiin". Lisää kuvaukseen toistamisohje ja ehdotettu korjaus.
Lue issue 12, tee korjaus omalle haaralle, aja testit ja tee commit. Älä pushaa vielä.
Tee muutoksista pull request (GitHub) tai merge request (GitLab), jonka kuvauksessa kerrotaan mitä muutettiin ja miksi.

Huomaa, että issueiden sisältö on muiden kirjoittamaa tekstiä. Claude lukee sen osana työtä, ja teksti voi sisältää ohjeita, jotka yrittävät ohjata sitä. Tarkista, mitä Claude aikoo ajaa, ennen kuin hyväksyt.

Julkaiseminen on vaihe, jota ei voi peruuttaa: git push, issuen luonti ja pull request näkyvät muille. Pidä nämä lupakysymyksen takana.

Harjoitukset

1. Kopioi repo ja kysy sen historiasta

Edellyttää: Pro-tilaus ja Git for Windows. Ei Prota? Seuraa kouluttajan demoa (Max) tai tee parin kanssa.

Kloonaa kurssin repo github.com/Marcozarg/ClaudeKurssi, käynnistä claude kansiossa ja kysy: "Näytä viimeiset 5 committia ja kerro, mitä kukin muutti."

Näytä esimerkkivastaus

Claude ajaa komennon git log (esimerkiksi git log -5 --stat) ja kertoo kunkin commitin muutokset: mitkä tiedostot lisättiin tai muutettiin. Tämä on lukua, joten Claude Code ei yleensä kysy lupaa. Tarkista tulos itse ajamalla git log --oneline -5.

2. Skriptin muutos omalle haaralle

Edellyttää: Pro-tilaus ja Git for Windows. Ei Prota? Seuraa kouluttajan demoa (Max) tai tee parin kanssa.

Tee uusi kansio, aja git init ja lisää PowerShell-skripti, joka lukee CSV-tiedoston käyttäjistä (nimi, osasto, sähköposti) ja poistaa tyhjät rivit ja kaksoiskappaleet. Tee ensimmäinen commit. Pyydä sitten Claudea: "Luo haara siistiminen, lisää skriptiin sähköpostiosoitteen tarkistus regexillä ja tee commit." Katso lopuksi git log --oneline ja git diff main.

Näytä esimerkkivastaus

Claude luo haaran (git switch -c siistiminen), lisää tarkistuksen esimerkiksi muodossa $email -match '^[^@\s]+@[^@\s]+\.[^@\s]+$' ja tekee commitin kuvaavalla viestillä. Diff näyttää vain lisätyt rivit. Jos päähaaran nimi on master, käytä komentoa git diff master. Testaa regex itse esimerkkiosoitteilla: se on yksinkertainen eikä hyväksy kaikkea, mitä sähköpostiosoitteissa sallitaan.

3. Issue Clauden kanssa (GitHub tai GitLab)

Edellyttää: Pro-tilaus sekä GitHub- tai GitLab-tili ja testirepo, johon saat luoda issueita. Ei Prota? Seuraa kouluttajan demoa (Max) tai tee parin kanssa.

Asenna gh tai glab ja kirjaudu. Pyydä Claudea luomaan testirepoon issue: "Luo issue: 'Runbook: palvelun uudelleenkäynnistys'. Kuvaukseen tarkistuslista: tarkista tila, pysäytä, käynnistä, varmista." Pyydä sitten listaamaan avoimet issuet ja sulkemaan luomasi issue.

Näytä esimerkkivastaus

Claude käyttää komentoa gh issue create (GitLabissa glab issue create), listaa issuet komennolla gh issue list ja sulkee issuen komennolla gh issue close (glab issue close). Jokainen komento pyytää luvan, ellet ole sallinut sitä: lue komento ennen hyväksymistä. Tarkista tulos selaimessa. Käytä testirepoa, älä oikeaa työrepoa.

Lisä: Projects, boardit ja turvallinen työtapa

  • GitHub Projects: komennot gh project (esimerkiksi item-list, item-add) vaativat project-oikeuden: gh auth refresh -s project. Pyydä Claudea: "Listaa projektin avoimet tehtävät ja ehdota, mikä otetaan seuraavaksi."
  • GitLab-boardit perustuvat labeleihin: kun issuen label vaihtuu, se siirtyy sarakkeesta toiseen. Pyydä: "Lisää issueen 12 label 'In progress'."
  • Rajaa oikeudet: käytä kirjautumisessa tunnusta, jolla on vain tarvittavat oikeudet, ja testaa ensin testirepossa.
  • Gitin virheiden korjaus: väärä commit voidaan yleensä korjata, mutta pushattua historiaa ei kannata kirjoittaa uusiksi. Kysy Claudelta vaihtoehdot ennen kuin ajat komentoja, joiden nimessä on --force tai reset --hard.
  • Lue lisää: gh issue ja glab issue.
