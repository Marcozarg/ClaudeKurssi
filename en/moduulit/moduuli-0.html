What is Claude?

Core ~45 minOptional ~10 minFree

Claude in brief

Claude is an AI assistant made by Anthropic. You write to it in plain language, and it answers with text, code, tables or whole documents. You can also attach files, images and logs.

You use Claude in the browser at claude.ai, in the desktop and mobile apps, and in the programming tool Claude Code. They all share the same account and the same usage limits.

In this course you first learn to use Claude in conversation (modules 0-5). After that you see how Claude Code works directly on your own machine (modules 6-10).

What Claude can and cannot do

Claude is good at

  • explaining an error message, a log line or an unfamiliar command
  • writing and fixing PowerShell scripts, regexes and SQL queries
  • summarizing a long text and shaping a ticket reply or a guide
  • converting data from one form to another, for example CSV to a table
  • brainstorming and going through options

Claude does not

  • see your environment: it does not know your servers, versions or settings unless you tell it
  • always know the latest changes: its knowledge is from a certain point in time unless it searches the web
  • remember earlier conversations automatically, unless the memory feature is on
  • always get it right, even when the answer sounds sure

Claude can be confidently wrong

Claude produces text that looks plausible. Sometimes it invents things that do not exist: a cmdlet parameter, a registry key path, a setting name, or the version in which a feature supposedly appeared. This is called a hallucination. The answer sounds just as confident when it is wrong as when it is right.

Make checking a habit before you run anything in production:

  • Read the help: Get-Help Get-ADUser -Parameter * or Get-Command -Syntax shows whether a parameter exists.
  • Run it safely first: in a test environment, with the -WhatIf switch, or as a read-only operation.
  • Check the source: ask Claude which documentation the answer is based on, and open it yourself.
  • Ask back: "Are you sure this parameter exists? From which version?" Claude often corrects itself when you ask it to check.

What you never paste

Everything you paste into Claude goes to Anthropic's service. Do not paste:

  • credentials and secrets: passwords, API keys, tokens, connection strings, private keys of certificates
  • customer and user data: names, personal identity numbers, emails, phone numbers, personal data in tickets
  • directory exports: AD or Entra user lists, group memberships, org charts
  • raw logs: a log often contains usernames, IP addresses, server names and sometimes passwords
  • internal information: network diagrams, firewall rules, vulnerability reports, contracts
Follow your own organization's AI guidelines. If your organization has a policy on using AI, it always takes precedence over this course. If you do not know whether you may paste something, do not paste it and ask first.

Anonymizing a log

A log is useful to Claude once you remove the identifying details. Replace them with placeholders that keep the structure: the same user is always <USER1>, the same server always <SERVER1>. Claude can then still see what happened and to whom.

An example of an anonymized log excerpt:

2026-11-03 08:14:22 <SERVER1> Kerberos pre-authentication failed for <USER1> from <IP1>
2026-11-03 08:14:25 <SERVER1> Kerberos pre-authentication failed for <USER1> from <IP1>
2026-11-03 08:14:31 <SERVER1> Account <USER1> locked out, caller <WORKSTATION1>

After anonymizing, check by eye: is there a name, an email address, a server name or a path containing a username left anywhere?

Optional: ask Claude to write a PowerShell script that replaces IP addresses, emails and usernames in a log with placeholders. Test the script on an invented log, not a real one, and use it only after you have read it through.

The training setting and data retention

On Free, Pro, Max and Ultra accounts you decide yourself whether your conversations are used to improve Claude. The setting is under Settings > Privacy, the switch Help improve our AI models (the name may vary slightly).

SettingWhat happens
OnNew conversations may be used to train models, and they are kept in de-identified form for up to 5 years.
OffConversations are not used for training, and they are kept for 30 days.

Check the setting yourself right after you sign in. Do not assume it is off. Also note:

  • Incognito conversations are not used for training even if the setting is on.
  • A deleted conversation disappears from your history immediately and from the servers within 30 days.
  • Thumbs up or down feedback is stored separately and kept longer.
  • On an organization's Team and Enterprise accounts, conversations are not used for training.

Usage limits: how they work

Every plan has a usage limit. It is not a number of messages: it depends on how much Claude has to process. A long conversation, large attachments and a heavier model use more.

  1. 5-hour limit: usage is measured in five-hour windows, and the limit resets every five hours. On Ultra, verified accounts do not have this limit. If you hit the limit, Claude tells you when you can continue.
  2. Weekly limit: paid plans also have a weekly limit that covers all models together. The week resets at an account-specific moment that is shown in the usage view.
  3. Shared limit: claude.ai, the desktop app and Claude Code all use the same limit. An afternoon of Claude Code work therefore also shows up on the browser side.

How model and effort matter

What uses up the limit is how much text Claude reads and produces. These affect it:

  • Model: a heavier model uses the limit faster than a light one.
  • Effort: a higher effort level means more thinking and therefore more text processed.
  • Conversation length: with every message Claude processes the whole conversation so far again.
  • Attachments: large files and logs are read again with every message.
  • Caching: a Project's content is cached, and when it is reused it uses less of the limit (module 3).
  • Claude Code agents: one request can start many model calls and subagents, so a single task can use a lot.
A subscription is not billed per token. A heavier model and a higher effort use more of the limit, but Anthropic does not publish a ratio. The API prices below show the price differences between models in API use, not how much of your subscription limit is used.

The effort level descriptions paraphrase Anthropic's effort documentation. The levels are an order, not measured multipliers: a higher level thinks more and uses more, but how much depends on the task.

How to save your limit

  • Start with a lighter model. Sonnet is enough for most work; switch to a heavier one only if the answer is not good enough.
  • Lower the effort for simple questions. A short question does not need much thinking.
  • Start a new conversation for a new topic. A long conversation is read again with every message (module 1).
  • Paste only what is needed. Trim a log or file down to the part the question is about.
  • Write the request complete the first time. A precise first message saves rounds of corrections.
  • Keep an eye on usage. Check Settings > Usage, or /usage in Claude Code, and clear Claude Code's context between tasks with /clear (module 7).

Claude Code is not included in the free account. It requires at least a Pro plan (or an organization's Team or Enterprise account). Exercises

1. Find the mistake in Claude's answer

Requires: nothing, done on paper or on your own machine in PowerShell. No access to a machine? Work with a partner.

Someone asked Claude: "How do I list the AD users who have not signed in for 90 days?" and got this answer. The answer contains one invented thing. What is it, and how could you have noticed it before running the command?

Import-Module ActiveDirectory
Get-ADUser -Filter * -InactiveDays 90 -Properties LastLogonDate |
    Select-Object Name, SamAccountName, LastLogonDate |
    Sort-Object LastLogonDate
Show example answer

The Get-ADUser cmdlet has no -InactiveDays parameter. You can see that with Get-Help Get-ADUser -Parameter InactiveDays, which gives an error, or by running the command, which fails with the error "A parameter cannot be found that matches parameter name 'InactiveDays'".

A working approach is, for example:

Search-ADAccount -AccountInactive -TimeSpan 90.00:00:00 -UsersOnly |
    Select-Object Name, SamAccountName, LastLogonDate

Note that LastLogonDate updates with a delay, so the cutoff is not accurate to the day.

2. Anonymize a log excerpt

Requires: nothing. No machine at hand? Do it on paper with a partner.

Below is an invented log excerpt. Rewrite it so that it could be pasted into Claude. Keep the structure so that the course of events is still visible.

Nov 03 09:02:11 web-prod-03 sshd[2211]: Failed password for matti.virtanen from 203.0.113.45 port 51122
Nov 03 09:02:15 web-prod-03 sshd[2211]: Failed password for matti.virtanen from 203.0.113.45 port 51122
Nov 03 09:02:19 web-prod-03 sshd[2214]: Accepted password for backup-svc from 198.51.100.7 port 40022
Nov 03 09:02:19 web-prod-03 sudo: backup-svc : TTY=pts/0 ; PWD=/srv/backup ; COMMAND=/usr/bin/rsync
Show example answer 
Nov 03 09:02:11 <SERVER1> sshd[2211]: Failed password for <USER1> from <IP1> port 51122
Nov 03 09:02:15 <SERVER1> sshd[2211]: Failed password for <USER1> from <IP1> port 51122
Nov 03 09:02:19 <SERVER1> sshd[2214]: Accepted password for <SERVICEACCOUNT1> from <IP2> port 40022
Nov 03 09:02:19 <SERVER1> sudo: <SERVICEACCOUNT1> : TTY=pts/0 ; PWD=/srv/backup ; COMMAND=/usr/bin/rsync

The person's name, the service account name, the server name and the IP addresses have been replaced. The same value always gets the same placeholder, so Claude can still see that the same user tried twice from the same address. The ports, times and command can stay, because on their own they do not identify anyone.
