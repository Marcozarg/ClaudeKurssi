What can you build with Claude Code?

At the end the instructor shows three of their own hobby projects. They were made in free time for a home network, not at work. Each was built with Claude Code in the same way of working you learned in modules 9 and 10:

  1. The idea is worked through with Claude one question at a time (grilling).
  2. Claude writes the specification and breaks it into tickets.
  3. Claude implements one ticket at a time, tests first, and the instructor reviews and tests every change.

The instructor's job was to decide what to build, answer Claude's questions, check the result and test it in the real environment.

The demos do not show server names, addresses or secrets. The same goes for you: when you show your own work, hide them first.

Electricity tracker

A web application that reads a household's electricity bills and consumption data as they are, compares years with each other and forecasts the future cost. The pages are in Finnish.

  • What Claude did: readers for the bills of several electricity companies, the comparison and forecast calculation, and tests that check the figures against example bills.
  • Lesson: give Claude an example file (with personal data removed) and the expected result. Then a test tells you whether the answer is right, and you do not have to guess.
  • About 140 commits in three weeks.
[KUVA: m11-sahkonseuranta - the comparison page, two years side by side]

LinuxManager

A web application that keeps a set of Linux servers updated and monitored over SSH from one page: updates, shared configuration files, disk space, Docker containers and a security check.

  • What Claude did: the whole application, its scheduled jobs and SSH connections, a preview before every change to a server, and a block list of servers the application must not touch.
  • Lesson: plan dangerous operations first. In the planning phase, ask Claude what can go wrong and how to see the change before it is made.
  • About 240 commits in a month.
[KUVA: m11-linuxmanager - the Dashboard, server names blurred]

3D Print Manager

An application that follows a 3D printer through its own interface: print history, control of power sockets and the camera image on the same page. It replaced a ready-made program used before.

  • What Claude did: monitoring of the printer's state, saving the history, the camera image and tests that are run without a real printer.
  • Lesson: Claude runs all the tests it can reach and gives the human only the steps that need a real device.
  • About 70 commits in two weeks.
[KUVA: m11-printmanager - the print view and the camera image]

The best way to learn is to take one small, recurring task of your own and do it with Claude next week.

Exercises

1. Your own idea, one question at a time

Requires: a Claude account (Free is enough).

Pick one small tool that would make your work easier, for example a script that lists expiring certificates. Write to Claude: "I want to make a tool that <description>. Ask me one question at a time until you know enough, and then write a short specification: goal, inputs, outputs, what it does not do." Answer the questions.

Show example answer

Claude asks, for example: where the certificates come from (the Windows certificate store, files, remote servers), how many days ahead to look, what form the result should take (CSV, email, screen) and whether the tool runs on a schedule. Finally it writes a specification that also has a limit, for example "does not renew certificates". If it did not ask about the limit, ask it to add one.

2. Your own follow-up plan

Requires: a Claude account (Free is enough).

Write down three recurring work tasks where Claude could help. For each, mark whether claude.ai (modules 0-5) is enough or whether Claude Code (modules 6-10) is needed, and which information in the task is something that must not be pasted in (module 0).

Show example answer
  • Drafts of ticket replies: claude.ai is enough; customers' names and contact details are removed first.
  • Explaining errors in logs: claude.ai is enough; the logs are anonymized.
  • Maintaining PowerShell scripts in a repo: Claude Code; credentials stay in a secret store, not in the script or the conversation.

Optional: before you build your own

  • Start small: one script or one page, not a whole system.
  • Keep the work in git from the start (module 8), so every change can be undone.
  • Check your organization's guidance on whether work tasks may be done with AI and with which account.
